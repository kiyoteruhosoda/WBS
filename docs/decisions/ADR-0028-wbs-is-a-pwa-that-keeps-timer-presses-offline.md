# ADR-0028: WBS を PWA にし、打刻はつながらないときも端末に溜めて押した時刻で送る

- 状態: 承認
- 日付: 2026-10-02
- 関連: task #192、ADR-0018（打刻の `at`）・ADR-0019（打刻アプリの戻り先と App Links）・ADR-0011（版）、
  打刻アプリ wbstimer の ADR-0011（押下を端末に残してから送る）、雛形 fastapitemplate の ADR-0035（新しい版の知らせ）

## 背景

持ち主の依頼は「wbs.nolumia.com を PWA にしたい」。ホーム画面に置けて、開けば「今日」が出て、電波の無い
ところで押した Start / Stop も失われないこと。

WBS の事情:

- ログインは SSO（assay）で、セッションは HttpOnly の Cookie。ログインの往復は `/api/auth/*`（assay への転送を含む）
- 画面は nginx（`frontend/Dockerfile`）が静的に配り、`/api/*` を api へ通す。nginx 自体はログインを求めない
- `/app/oauth2redirect` は打刻アプリ（wbstimer）のログインの戻り先で、Android の App Links が受け取る URL。
  検証ファイル `/.well-known/assetlinks.json` は api が作る（ADR-0019）
- 雛形・nolumiatask は `vite-plugin-pwa`（workbox）で PWA にしている。WBS の CI は `npm ci` で、依存を足すと
  `package-lock.json` の作り直しが要る（手元で解決しない決まり）

## 決定

1. **manifest は静的なファイル**（`frontend/public/manifest.webmanifest`）。名前・短い名前は「WBS」、`start_url` と
   `id` は `/`（「今日」）、`display: standalone`、`theme_color` は画面の主色 `#0017C1`、`background_color` は
   画面の地 `#F2F2F2`。アイコンは 192・512・maskable 512・apple-touch-icon と favicon.svg を
   `scripts/generate_pwa_icons.py`（雛形と同じ標準ライブラリだけの作り）で生成してコミットする。図柄は WBS の木
   （上の 1 つの箱から下の 3 つへ分かれる）。
2. **Service Worker は自前で書き、依存を足さない**（`frontend/src/serviceWorker/sw.ts`）。Vite の 2 つ目の入口として
   束ね、焼くときに `vite.config.ts` の `serviceWorkerShell` が**殻の一覧（index.html・ハッシュ付きの assets・
   public のファイル）と、その中身から作った版**を書き込んで `/sw.js` として出す。中身が変われば `sw.js` も変わる。
   - **持つのは画面の殻だけ。** 画面の遷移には殻の index.html を返し、静的ファイルは殻から返す（無ければネットワーク）。
   - **`/api/*`・`/app/*`・`/.well-known/*`・`/sw.js`・GET 以外・よそのオリジンには手を出さない**（`respondWith` を呼ばない。
     判定は純関数 `requestRoutes.ts` の `routeOf`）。ログインの転送も、打刻アプリの戻り先も、App Links の検証も、
     版（`/api/info`）も素通し。データは一切キャッシュしない。
   - install で殻を 1 つずつ取って入れる（`cache.addAll` は使わない。1 つ取れないと登録ごと落ちる）。
     転送・エラー・よその応答は殻に入れない。有効になったら古い版の殻を消す。
   - ⚠ Service Worker の束は**ほかの束を import してはいけない**（古典的なスクリプトとして登録する）。画面の束から
     `requestRoutes.ts` を読まない。読むと共有の束ができ、`serviceWorkerShell` がビルドを落とす。
3. **新しい版は知らせるだけで、入れ替えは押したとき**（雛形の ADR-0035 と同じ形）。新しい Service Worker は待たせ、
   待っている版があれば画面の下に「新しい版があります [読み込み直す]」を押すまで出す。押すと `SKIP_WAITING` を送り、
   制御が移ったら（合図が来なければ 2 秒後に）読み直す。更新の確認は 30 分ごとと、タブが手前に戻ったときに自分で起こす。
   ログイン画面でも出す。開発サーバでは登録しない。
4. **nginx は sw.js・manifest・アイコンを認証の外で、そのまま配る。** `sw.js`・`index.html`・SPA の遷移・manifest は
   `Cache-Control: no-cache`、`/assets/` だけ 1 年・immutable。`/sw.js`・`/manifest.webmanifest`・`/assets/` は
   **無ければ 404**（index.html を 200 で返さない。Service Worker が HTML を JavaScript として殻に入れるのを防ぐ）。
5. **打刻の Start / Stop は、まず端末（IndexedDB）に残し、それから古い順に送る。** wbstimer の ADR-0011 と揃える:
   - 押した時刻を**サーバの時計に寄せて**（`/current` の `server_now` と端末の時計の差を足して）残し、API の `at` で送る。
     控えが無ければ端末の時計のまま
   - 送るのは**古い順に 1 件ずつ**。送れない 1 件で止め、後ろは残す
   - **捨てるのは 409 / 422 だけ**（サーバが二度と受け取らない: 重なり・確定済みの締めの期間・7 日より前・未来）。
     加えて **7 日より前の押下は送らずに捨てる**（ADR-0018 の上限）。401・403・5xx・応答なしは残して止める
   - 押下には押した人（`user_id`）を付け、送るのはログイン中の人の分だけ（同じブラウザで別の人がログインしても送らない）
   - 同時に 2 つの送信を走らせない（タブの中は 1 本にまとめ、タブどうしは Web Locks）。送っている間に押された分も続けて送る
   - 画面は押した瞬間に変える（溜まった押下を「いまの打刻」の控えに重ね、最後の押下が勝つ）。溜まった Start は
     まだサーバに無いので、タスクの付け替えはできない
   - 上部の打刻ボタンの横に「未送信 n 件」。送り直すのは、開いたとき・つながったとき（`online`）・画面に戻ったとき・
     溜まっている間は 30 秒おき
   - 知らせ: つながらないだけなら出さない（件数で足りる）。つながっているのに残した（5xx 等）は「端末に残してあり、
     あとで送り直す（押し直さなくてよい）」、捨てたら「記録できなかった。締めの画面で直す」とサーバの理由
   - IndexedDB が開けない（プライベートの窓の一部等）ときは、タブの中だけの置き場に切り替える（タブを閉じると消える）
   - **Web でも、つながっているときも同じ道を通る**（つながっていれば押してすぐ送れる）。押した時刻は常に `at` で送る
6. **オフラインで開いたときは殻を出し、取れないことを「オフラインです」と出す。**
   - ログインを確かめられない（`/api/auth/*` が応答なしで落ちた）ときは、**最後にログインしていた人の控え**
     （`localStorage` の名前とログインの設定。秘密は持たない）で中身を描く。控えが無ければ「オフラインです。
     つながってから開き直して」。つながったらサーバの答えが勝つ（ログインが切れていればログイン画面）。ログアウトで消す
   - 「オフラインです」は、端末が電波なしと言うか、直前の取得が応答なしで落ちたときに上部へ出し、何か取れたら消す

## 理由

- **依存を足さなかった。** `vite-plugin-pwa` を入れれば雛形とそろうが、lockfile の作り直しが要る（手元で `npm install`
  しない決まり）。WBS が要るのは「殻だけを持つ」「いくつかの経路に触らない」「新しい版を待たせる」の 3 つで、
  workbox の大半（実行時のキャッシュの戦略・期限）は使わない。自前でも 100 行ほどで、触らない経路の判定を純関数にして
  試験できる。見た目の振る舞い（知らせの出し方・押したときの読み直し・確認の起こし方）は雛形と同じにした。
- **触らない経路を絞った。** Service Worker が `/api/auth/*` の転送を掴むとログインが壊れ、`/app/oauth2redirect` を
  殻の index.html で返すと、打刻アプリへの戻りがブラウザの中の SPA で止まる。データをキャッシュしないのは、
  古いデータを今のものに見せないため（オフラインなら「オフラインです」と言う）。
- **sw.js を認証の外で、no-cache で配る。** Service Worker のスクリプトは転送された応答では登録できず、登録が外れると
  ホーム画面に置けなくなる。古い sw.js が HTTP のキャッシュに残ると新しい版に気付けない。
- **押した時刻で送る。** 送った時刻で記録すると、電波の無いところの打刻が全部ずれる（ADR-0018）。
- **つながっているときも溜めてから送る。** 「送れなかったら溜める」だと、送る途中でタブを閉じた・応答を受け取り損ねた
  押下が消える。溜めてから送れば 1 本の道で済み、試験も 1 つで済む。サーバは走っている打刻と同じ時刻の Start を
  送り直しとして扱うので、受け取り損ねて送り直しても害が無い。
- **409 / 422 だけ捨てる。** 残すと先頭で詰まり、後ろが永遠に送れない。それ以外は待てば通りうる。
  401 で捨てないのは、ログインし直せば同じ人として送れるから。
- **最後にログインしていた人で殻を描く。** 控えが無いとオフラインではログイン画面しか出せず、打刻を溜める場所が無い。
  控えるのは表示名とログインの設定だけで、オフラインの間に読めるデータは無い（データはキャッシュしない）。

## 影響

- **確かめられるのは本番の束だけ。** Service Worker は `vite build` でしか焼かれず、開発サーバでは登録しない。
  CI は焼けること（`serviceWorkerShell` が入口・import・目印を見て落とす）と純関数の試験までを見る。
  ホーム画面に置けること・オフラインで開くこと・新しい版の知らせは、配った後に本番で確かめる。
- 新しい版の知らせが出るまでの遅れは最大 30 分（＋タブを手前に戻したとき）。
- オフラインで開いたとき、各画面は「データの読み込みに失敗しました」を出す（「今日」も）。打刻ボタンは押せる
  （走っているかどうかが分からないときは「開始」を出す。走っていれば、サーバが止めて切り替える）。
- 端末に溜まった押下はタブを閉じても残り、次に開いたときに送る（バックグラウンドの送信は無い。wbstimer と同じ）。
- 「今日」の画面の打刻の失敗の知らせは、上部の打刻ボタンの 1 か所に寄せた（同じ押下の結果を 2 か所に出さない）。
- アイコンを変えるときは `scripts/generate_pwa_icons.py` を直して流し直す（出力物を手で直さない）。
