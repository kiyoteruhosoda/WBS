# ADR-0068: 機械が書いた操作は表に残す（読む口はアプリログまで）

- 日付: 2026-10-31
- 状態: 承認

## 文脈

機械のトークンの最小権限（task #715）の仕上げで、機械が書く操作を「どの機械が・誰の分を・何を」で引けるようにすることになった（task #802）。ほかのアプリは雛形の監査ログ（`machine_operation.performed`）へ残すが、WBS には監査ログの表も画面も無い。

WBS の機械の口は 3 本で、書くのは Tracker の締めの時間（`PUT`・`DELETE /api/machine/closed-periods/{first_day}`）だけ。これは利用者の実績（`actual_hours`）を変える。

## 決定

- 表 `machine_operation_logs` を足し、書く 2 本は `client_id`・利用者・操作（経路の型）・件数を入れる。**書いた内容と同じトランザクション**で入れ、書けたのに記録が無い状態を作らない。
- 読む 2 本（担当タスク・プロジェクト）は表に残さず、アプリログ（`machine_reader_call`。`client_id` と利用者の id）までにする。Tracker の画面が開くたびに読むので件数が多く、変わるものも無い。
- 断った操作（トークン違い・期間の外）は表に残さない。トークン違いは `client_id` が確かでなく、期間の外は何も変えていない。
- 画面は作らない。見るときは DB を読む（`SELECT * FROM machine_operation_logs ORDER BY id DESC`）。

## 理由

雛形の監査コンテキストを持ち込むと、一覧の画面・権限・保持期間まで要るのに、残すのは締めのたびの数行だけである。消す仕組みも同じ理由で持たない（利用者 1 人で月 2 回ほど）。

## 影響

書く口を足すときは同じ表へ残す。Scheduler は書く口を持たないので表を持たない（Scheduler の ADR-0069）。
