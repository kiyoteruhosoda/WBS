# ADR-0033: 予定のカレンダーに「仕事 / プライベート」の区別を持つ

- 状態: 承認
- 日付: 2026-10-02

## 背景

持ち主（task #191、2026-10-02）: 「仕事をベースの予定として、プライベートの予定を管理したい」。予定のカレンダーは
ADR-0027 で複数にしたが、どのカレンダーの予定も計画（実績の「予定した時間」・締めの予定）と打刻の既定のタスクに
同じく数えていた。

## 決定

- 予定のカレンダー（`calendars`、種類 `EVENTS`）に区別 `scope`（`WORK` / `PRIVATE`）を持つ。既定は仕事。移行 `0014` で
  列を足し、既存のカレンダー（既定のカレンダー・休みの層を含む）はすべて仕事。**既定のカレンダーと休みの層は
  プライベートにできない**（422。既定は「時間を取る」のタスクの予定・消したカレンダーの予定の行き先のため）。
- **プライベートのカレンダーの予定**:
  - タスクを結べない（分類をタスクにできない）。作る・直す・切り出す・分けるで、プライベートのカレンダーにタスクを
    結んだ予定を入れると 422。タスクを結んだ予定のあるカレンダーはプライベートにできない（409）
  - 実績の「予定した時間」（`/api/actuals` の期間別・予定 vs 実績）に数えない
  - 打刻の既定のタスク（予定のタスク、ADR-0008）とタスクの「予定済みの時間」（ADR-0014）に使わない
  - **締めの画面には出さない**（予定の列にも、「打刻の無い予定」の指摘にも）。締めは仕事の時間を確定する場なので、
    薄く出す・切り替えるより、出さない方が迷わない
  - カレンダー（月・週・平日）と「今日」には出す。見た目で分ける: 予定の色の上に白い細い斜線（色だけに頼らない）。
    日の一覧（選んだ日）には「プライベート」の印
  - 通知（アラーム・端末への通知）は仕事と同じく出す
- 回の一覧（`GET /api/calendar/occurrences`）に `is_private` を足す。
- **画面**: カレンダーを作る・直すダイアログに「プライベートのカレンダー」の切り替え（既定のカレンダーは切り替えられない）、
  一覧の名前の横に「プライベート」の印。プライベートのカレンダーがあるときは一覧の上に「仕事だけ」の一括切り替え
  （プライベートを隠し、仕事のカレンダーと休みの層を出す。表示の組み合わせとして保存もできる）。予定の編集画面で
  プライベートのカレンダーを選ぶと、分類は予定になり、タスクの欄は消える。「時間を取る」のタスクの予定は
  プライベートのカレンダーには入れない（表示中の仕事のカレンダー、無ければ既定）。

## 理由

- 区別をカレンダーに持たせたのは、Google カレンダーと同じく「どのカレンダーに入れるか」で決まる方が、予定ごとに
  印を付けるより迷わないため。表示の選択・組み合わせ（ADR-0027）でそのまま「仕事だけ」が作れる。
- タスクを結べなくしたのは、プライベートの予定のタスクが打刻の既定・予定済みの時間に入ると「数えない」と矛盾するため。
  数えないだけにすると、結んだタスクの予定済みの時間が二重の意味を持つ。
- 「仕事だけ」を固定の組み合わせとして作らず一括の切り替えにしたのは、既存の「休みだけ」と揃え、利用者ごとに
  組み合わせを作って回る移行を避けるため。

## 影響

- 移行 `0014`（`down_revision` は `0013`）。下げると列が消え、プライベートだったカレンダーは仕事に戻る。
- 締めの画面で「予定どおりやった」を 1 操作で打刻にする口（ADR-0012）は、プライベートの予定には出ない。
