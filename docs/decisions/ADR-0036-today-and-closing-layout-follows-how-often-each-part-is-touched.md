# ADR-0036: 「今日」と締めの画面も触る頻度で並べ、常時出す必要の薄い物をしまう

- 状態: 承認
- 日付: 2026-10-02
- 関連: task #151・ADR-0035（カレンダーで同じ原則。task #191）・ADR-0015 / 0022（「今日」）・ADR-0016 / 0026（締め）

## 背景

持ち主の原則（2026-10-02）:

> 一番触るものを上や左の目立つ所が良いし、極端に触る頻度が低いものは常時出したくない。

カレンダー（`/calendar`）はこの原則で並べ直した（ADR-0035）。そのとき「今日」と締めにも常時出す必要の薄い物が
あると挙げていた（ADR-0035 の「影響」）。

- 「今日」（`/`）: 右の列のいちばん下に「全体の進捗」のカード（完了の割合・今週完了・期限超過）。
- 締め（`/closing`）: 操作の行の右に、格子の操作の説明文「押して選ぶ・引いて動かす・…」が常に出ていた
  （狭い画面では 2 行、格子を約 45px 押し下げる）。
- 締め: 「気になる打刻」の 320px の列が 0 件でも出ていた（「気になる打刻はありません」の 1 行のために、1440px の画面で
  格子の幅が 836px に削られる）。

## 頻度の見立て

持ち主 1 人が毎日使う前提。

### 「今日」

| 順 | 部品 | 頻度の見立て |
|---|---|---|
| 1 | 打刻（走っている打刻・停止・いまの予定から Start） | 開くたびに。日に何度も |
| 2 | 今日の予定のグリッド（見る・予定を作る・動かす・▶ で始める） | 開くたびに |
| 3 | 今日やること（タスクの分類の回の済み・▶） | 有る日は開くたびに |
| 4 | まだ時間を取っていないタスク（時間を取る） | 朝に 1 回・予定を組むとき |
| 5 | 今日の実績（タスク別の打刻の長さ） | 日に数回見る（合計は 1 の打刻の欄にも出ている） |
| 6 | 元に戻す・やり直し | 動かし間違えたときだけ（灰色の小さなアイコンのまま） |
| 7 | 全体の進捗（完了 x / 全 y・今週完了・期限超過） | 今日の作業には使わない。期限超過のタスクは 4 の一覧に「期限切れ」として既に出る。振り返りのときに見る物 |

### 締め

| 順 | 部品 | 頻度の見立て |
|---|---|---|
| 1 | 格子（予定と打刻・選ぶ・動かす・伸ばす・足す） | 開くたびに何度も |
| 2 | 未割当を選ぶ → タスクを振る（選んだときの操作） | 締めの主な仕事。開くたびに |
| 3 | 確定する | 期間に 1 回。ただし締めの終わりの 1 手で、上の行の右端にある（いまのまま） |
| 4 | 気になる打刻の一覧 | 件数があるときは、ここから飛んで直す。0 件なら見る物が無い |
| 5 | 日ごとの合計の表 | 確定の前に 1 回見る（いちばん下のまま） |
| 6 | 分ける | 時々（1 本を 2 つに割るときだけ） |
| 7 | 期間の切り替え | まれ（開くといちばん古い未確定の期間が選ばれている） |
| 8 | 操作の説明 | 最初の数回だけ読む |

## 決定

### 「今日」

- **全体の進捗のカードを「今日」から外し、実績の画面（`/actuals` のタスクの表）の上の行に 1 行で寄せる**
  （`components/actuals/OverallProgress.tsx`）。実績の画面は「予定と実績・計画と実績」を振り返る所で、全体の進捗と
  同じ使い方をする。中身（完了の割合・完了 x / 全 y・今週完了・期限超過）は同じ。範囲（プロジェクト）に依らず全部の
  タスクの数（`/api/dashboard/kpi` のまま）。
- 残りの並びは変えない（スマホ幅: 打刻 → 今日やること → 予定のグリッド → まだ時間を取っていないタスク → 今日の実績。
  広い画面: 左にグリッド、右に打刻 → 今日やること → 時間を取っていないタスク → 今日の実績）。見立ての 1〜5 の順に
  既に並んでいる。

### 締め

- **操作の説明は ? のボタン（操作の行の右端）にしまう。** 押すと説明のポップオーバーを開く（ツールチップにしないのは、
  指ではツールチップが出ないため）。**この端末で初めて締めを開いたときだけ、自分で開いて見せる**。閉じたら端末に覚えて
  （localStorage `wbs.closing.helpSeen`）、次からは出さない。覚えられない端末（プライベートの窓など）では自分では開かない
  （毎回開くと最初の 1 手を奪うため）。
- **「分ける」の最中だけ、次に何を押すかの 1 行（「打刻の分けたい位置を押してください…」）を操作の行の下に出す。**
  その間は要る説明なので、しまわない。
- **気になる打刻が 0 件なら、320px の列を出さず、操作の行の右に「✓ 気になる打刻はありません」の 1 行だけ出す。**
  格子はその幅を使う（1440px の画面で 836px → 1168px）。1 件でもあれば今までどおり列（広い画面は右、狭い画面は格子の下）。
  確定済みの期間でも同じ行に出す。
- **操作の行は左に締めの主な仕事、右に時々使う物。** 左から「未割当を選ぶ（n）」・選んだときの操作（タスクを振る・
  つなぐ・時刻を直す・消す・選択を解除）。右端に寄せて「気になる打刻はありません」・「分ける」・?。前は「分ける」が左端に
  あり、主な仕事の「未割当を選ぶ」がその右だった。
- **狭い画面では期間の行を 1 行に収める。** 欄は年を省いた「9/16〜9/30」（開いた一覧には年まで）、状態のチップ
  （未確定・確定済み）は出さない（未確定なら「確定する」、確定済みなら「開け直す」と緑の知らせが同じことを言う）。
  広い画面は年とチップを出す。欄の中の「— 未確定」は、チップと二重なので選んだ値からは外した（一覧には残す）。
  412px の画面で格子の上端は 284px → 195px。
- 確定済みの知らせの「残を見直す」が狭い画面で 1 文字ずつ縦に折れていたので、折り返さないようにした。

## 理由

- 目立たせるのは重要度ではなく頻度（ADR-0035 と同じ）。全体の進捗は「今日」の 1 枚のうち、今日の作業に答えない唯一の
  カードだった。期限超過の数は気にすべきだが、その中身（どのタスクか）は「まだ時間を取っていないタスク」に「期限切れ」として
  出ていて、数だけを毎日見せる理由は薄い。消さずに実績の画面へ寄せたのは、振り返るときには要るから。
- 説明文は一度読めば要らないが、初めての人には要る。最初の 1 回だけ開いて見せ、あとは ? に置けば、両方を満たす。
- 0 件の列を残すと、いちばん触る格子が毎回 1/4 の幅を失う。0 件であることは 1 行で伝わる。1 件以上のときに列にするのは、
  一覧から飛んで直すのが締めの段取りの一部だから（行に詰めると件の中身が読めない）。
- 「分ける」を右へ寄せたのは、選んだときの操作が左に出入りしても位置が動かないようにするため（前は左端の固定の位置にあった
  が、頻度は低い）。

## 影響

- 「今日」から全体の進捗が見えなくなる（実績の画面のタスクの表の上に移る）。
- 締めの説明は ? を押すまで見えない（初回だけは自分で開く）。
- 文言: `closing.help`（操作の説明）・`closing.periodLabelShort`（年を省いた期間）を足した。
