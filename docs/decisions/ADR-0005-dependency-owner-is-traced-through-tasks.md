# ADR-0005: 依存の持ち主は、列を足さずにタスクを辿って見る

- 状態: 承認
- 日付: 2026-10-01
- 関連: task #164

## 背景

`task_dependencies` は `(predecessor_task_id, successor_task_id)` の組だけを持ち、持ち主（`user_id`）の
列が無い。ガントと循環の検査は**全員分の依存を引いてから**自分のタスクで絞っていた。
表示は自分のタスク同士に絞っていたので画面には出ていなかったが、利用者が増えると読む量が
全員分に比例し、絞り忘れた口が 1 つでもあれば他人の依存がそのまま漏れる形だった。

## 決定

**依存の読み出しは、両端のタスクを `tasks` へ結合して、どちらも同じ利用者のものだけを返す。**
リポジトリの口は `find_all_for_user(user_id)` / `find_by_task_for_user(task_id, user_id)` だけにし、
全員分を引く口は置かない。

書き込み（依存を足す）は従来どおり、両端のタスクが自分のものであることを先に確かめる。
消すときは後続（URL の `task_id`）が自分のものであることを確かめる。

## 理由

- **`user_id` の列を足す案**は採らなかった。持ち主は両端のタスクから一意に決まるので、列を足すと
  同じ事実を 2 か所に持つことになり、ずれたとき（タスクの持ち主が変わる・古い行）にどちらが正か
  決まらない。表の形を変えるとマイグレーションも要り、Alembic の導入（別 PR）と当たる。
- 片端だけ結合する案は採らなかった。入口で両端を見ているので通常は同じ結果になるが、
  古いデータに他人のタスクへ伸びた行が残っていた場合に混ざる。
- 結合は主キーで引くので、行数が少ないうちは費用は問題にならない。

## 影響

- 依存の読み出しは常に利用者 1 人分になる。他人のタスクを先行・後続にした行は、どの口からも見えない。
- 依存とガントのユースケースはドメインのリポジトリの口を受け取る形になり、インフラを直接
  import しなくなった（組み立てはルーター側）。
- 削除済みのタスクを端に持つ依存は、読み出しでは落とさない（従来どおり。ガントは表示側で落とす）。
