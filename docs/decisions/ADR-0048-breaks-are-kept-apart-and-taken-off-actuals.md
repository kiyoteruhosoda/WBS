# ADR-0048: 休みは打刻とは別に持ち、実績の長さから重なる時間を引く

- 状態: 承認
- 日付: 2026-10-13
- 関連: task #392（WBS 側）・#391（WinTrack 側）・#377、取り決め `CONTRACT.md` の節 6（改訂 3）、
  ADR-0012（締め）・ADR-0017（実績の見える化）・ADR-0045（Working が正）・ADR-0047（工数表）

## 背景

持ち主の要望: 「締め（Closing）には休みを出したい。実績（Actuals）は休憩時間を引いて」。WinTrack は PC で
作業と作業の間に手が止まった時間などを休みと決め、日ごとに WBS へ送る。

## 決定

1. 休みは**打刻とは別の表** `work_breaks`（`started_at`・`ended_at`・`source`。いまは `auto` だけ）に持つ。
   打刻を切り抜かない（Working は走ったまま）。表題やアプリ名は受け取らない。
2. 口（どちらも Bearer 可、`AppOrWebUserDep`）:
   - `PUT /api/breaks/auto/{日付}`（`time_zone` での日付）: その日に始まる自動の休みを**丸ごと置き換える**（送り直しても同じ。
     `[]` で全部消える）。区間はその日の中・重ならない・終わり > 始まり（違えば 422）。7 日より前・未来は打刻と同じ制限
     （未来は 60 秒まで今に寄せる）。確定済みの締めの期間に掛かる日は 409（`detail` は `closed`。置き換えない）
   - `GET /api/breaks?start=&end=`: 掛かる休みを始まりの順に
3. **実績の長さ = 打刻の長さ − その打刻と重なる休み。** 打刻を日ごと・タスクごとに割る共通の計算
   （`allocate_by_local_day`）に休みを渡し、締めの画面の日ごとの合計・締めの確定（`work_logs`）・実績の表示
   （`/actuals` の打刻の帳簿）の 3 か所で同じ計算を使う。重なる 2 本の打刻があれば、どちらからも引く。
   打刻の無い時間の休みは何も引かない。
4. 締めの画面の応答に期間の休み（`breaks`）を足し、工数表（ADR-0047）の業務の開始・終了の行の下に、日ごとの休みの
   合計と区間を出す。日の計は休みを引いたあとの値（サーバーの合計がそうなっている）。業務の開始と終了は変えない。

## 理由

- 打刻を切り抜く案は、Working（手の打刻）を WinTrack の判断で書き換えることになる（ADR-0045 で上書きは例外作業だけにした）。
  別に持てば、休みを直したときに打刻はそのままで、合計だけが変わる。
- 日ごとの丸ごとの置き換えにしたのは、PC 側で「作業に含める」に直したときに消せるようにするため（差分を送らせない）。
- 計算を 1 か所に寄せたのは、締めの確定と実績の表示で数字が食い違わないようにするため。

## 影響

- 移行 0021（`work_breaks`）。
- 「今日」の画面の今日の実績はまだ休みを引いていない（要望の外。要るなら次の課題）。
- 締めた期間を開け直して確定し直すと、その時点の休みで `work_logs` が作り直される。
