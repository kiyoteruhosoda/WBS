# ADR-0011: 締めの期間を別表に持ち、確定で打刻から work_logs を作る

- 状態: 承認
- 日付: 2026-10-01
- 関連: task #161（締め）・#163（締めの規則、決定済み）・#154 / ADR-0008（打刻）・ADR-0009（予定）・ADR-0010（進捗率）

## 背景

打刻（ADR-0008）は下書きで、月 2 回の締めで直して確定したものが実績（`work_logs`）になる（#152）。
#163 で規則が決まっている: 期間は 1〜15 日 / 16 日〜末日、区切りは利用者のタイムゾーンの 0:00、
日をまたぐ打刻は 0:00 で割る、確定後は読み取り専用で本人が開け直せる、丸めない、
締めの時期の知らせはアプリの上部に出す。ADR-0008 は「確定済みの期間は別表で持ち、打刻の行に印を
持たせない」見込みを書いていた。この段（#161 の第 1 段）は表・ユースケース・API までで、画面は次の段。

## 決定

### 表

| 表・列 | 中身 |
|---|---|
| `closing_periods` | **行がある = 確定済み。** `user_id`・`first_day` / `last_day`（利用者のタイムゾーンの日付、末日を含む）・`time_zone`（確定したときのタイムゾーン）・`starts_at` / `ends_at`（区切りの瞬間、naive な UTC の半開区間）・`closed_at`。`(user_id, first_day)` で一意。消した id を使い回さない |
| `work_logs.source` | `manual`（手で書いた。既存の行はすべてこれ）/ `closing`（締めで作った）。文字列（ネイティブ ENUM にしない） |
| `work_logs.closing_period_id` | 締めで作った行が、どの期間から来たか（開け直しで消すため）。索引付き |
| `work_logs.duration_seconds` | 締めで作った行の**正確な長さ（秒）** |

- 移行は `0005_closing_periods`（`down_revision = 0004`）。`work_logs` は SQLite のため `batch_alter_table` で列を足す。
- **期間は行の有無で表す**（状態の列を持たない）。開け直しは「締めで作った `work_logs` を消して、期間の行を消す」。
  確定と開け直しを何度繰り返しても、「確定した」という事実は行 1 つにしか無い。
- **確定済みかどうかは区切りの瞬間で判定する。** 期間の行に、確定したときのタイムゾーンで出した `starts_at` /
  `ends_at` を写しておく。あとで利用者がタイムゾーンを変えても、確定した範囲は動かない
  （日付だけを持つと、タイムゾーンを変えた瞬間に守る範囲がずれ、確定した打刻が書き換えられうる）。
- **`hours` は小数 2 桁に収め、正確な長さは `duration_seconds` に持つ。** `hours` は `NUMERIC(5,2)` で、
  分を時間に直すと割り切れない（20 分 = 0.333…）。「丸めない」（#163）は 15 分単位などへ寄せないことで、
  確定した長さを秒で残す。進捗率・ダッシュボード（ADR-0010）は今までどおり `hours` を足す
  （1 行あたりの差は 18 秒未満）。

### 確定（`POST /api/closing-periods/{first_day}/close`）

- 期間は初日（1 日か 16 日）で指す。区切りは利用者の設定のタイムゾーン（`users.timezone`）の 0:00。
- 期間に掛かる打刻を、利用者の日付ごと・タスクごとに足して `work_logs`（`source=closing`）を作る。
  日をまたぐ打刻は 0:00 で割る。期間の外にはみ出した部分は数えない（隣の期間の締めで数える）。
- **断る（409）**: 既に確定している・期間に掛かる打刻が走っている・**期間に掛かる未割当の打刻がある**
  （タスクが空、またはタスクが消えた）。`work_logs.task_id` は必須なので、未割当の時間を黙って落とさない。
  まとめて振る口（`/time-entries/assign`）で振るか、消してから確定する。
- まだ始まっていない期間は確定できない（422）。**今の期間は終わる前でも確定できる**（その後の Start は断る）。
- 重なり・止め忘れは**断らない**（気付かせるだけ）。直すかどうかは本人が決める。
- 手で書いた `work_logs` には触れない。

### 確定後の保護

確定済みの期間に掛かる打刻の作成・修正・削除・分割・結合・タスクの振り直し・Start / Stop を 409 で断る
（`TimeEntryUseCases` が `ClosingPeriodRepository.find_overlapping` を引く）。修正は**元の範囲と新しい範囲の
両方**を見る（開いている期間の打刻を、確定した期間へ動かすことも断る）。走っている打刻は終わりが無いものとして扱う。
締めで作った `work_logs` は実績の API から直せない（409。直すなら期間を開け直して打刻を直す）。

### 開け直し（`POST /api/closing-periods/{first_day}/reopen`）

本人ができる（#163）。締めで作った `work_logs` を**物理削除**し（打刻からいつでも作り直せる）、期間の行を消す。
確定していない期間は 409。

### 補正の API

| 操作 | 口 | 振る舞い |
|---|---|---|
| 締めの画面 1 枚分 | `GET /api/closing-periods/{first_day}` | 期間・打刻・予定の回（利用者のタイムゾーンへ投影済み）・日ごとタスクごとの合計（確定と同じ割り方）・気付かせる物 |
| 未確定の期間 | `GET /api/closing-periods/pending` | 今の期間より前で確定していない期間（いちばん古い打刻の期間から数える。2 年分まで） |
| 手で足す | `POST /api/time-entries` | `source=manual`。止まった打刻だけ |
| 分ける | `POST /api/time-entries/{id}/split` | `at` は始まりと終わり（走っていれば今）の間。元は `at` で終わり、続きは `source=split`（タスク・メモは同じ）。走っている打刻なら続きが走り続ける |
| つなぐ | `POST /api/time-entries/merge` | いちばん早い打刻が残り、最後の終わりまでの 1 本になる（間も含む）。タスクは指定か、早い方から最初に見つかったもの。走っている打刻はつなげない |
| まとめて振る | `POST /api/time-entries/assign` | `task_id: null` で未割当へ戻す |
| 予定の回から | `POST /api/time-entries/from-occurrence` | 回を（予定の id, 始まりの瞬間）で指す。`source=schedule`。終日の回・まだ終わっていない回は 422。タスクは回のもの（消えていれば未割当で、題名をメモに入れる） |

- 他人の打刻・予定は 404（ADR-0005）。まとめて扱う打刻は 1 回 500 本まで。
- 予定の回は `OccurrenceSource`（`CalendarEventUseCases.list_occurrence_views` を満たす口）で引く。
  打刻・締めのユースケースは予定の表に直接依存しない。

### 気付かせる物（期間の要約）

| 物 | 判定 |
|---|---|
| 止め忘れ | 長さが 12 時間超（ADR-0008 の `is_long_running`） |
| 重なり | 自分の打刻どうしが正の長さで重なる組（接しているだけは除く） |
| 未割当 | タスクが空、またはタスクが消えた・他人のもの |
| 予定はあったのに打刻が無い | 終わった時刻付きの回（終日は除く）の時間に、掛かる打刻が 1 本も無い |

## 理由

- **状態の列ではなく行の有無にした**: 「未確定」の行を前もって作る必要が無く、未確定の期間は打刻から数えられる。
  開け直しの後に残る行が無いので、「確定したのに `closed_at` が空」のような食い違いが起きない。
- **未割当があれば確定を断る**: 黙って落とすと実績が足りなくなり、気付けない。「未割当」という仮のタスクへ
  入れる案は、あとで本当のタスクへ移す手間が増えるうえ、進捗率を狂わせる。
- **今の期間を早めに確定できるようにした**: 15 日の夜に締めたい。終わるまで待たせると「上部の知らせ」が
  1 日遅れる。早く締めた後に打刻したくなったら開け直せばよい。
- **work_logs を開け直しで物理削除する**: 打刻（下書き）が正本で、締めの行はそこから決まる写しにすぎない。
  論理削除で残すと、確定と開け直しのたびに同じ内容の行が溜まる。

## 影響

- 締めの画面（#161 の次の段）は `GET /api/closing-periods/{first_day}` 1 本で描ける。上部の知らせは `/pending`。
- 打刻アプリ（#167）から確定済みの期間の時刻で Start / Stop を送ると 409 になる。
- MariaDB へ移すとき: 新しい表・列は素の型だけで、ADR-0008 の部分索引のような作り直しは要らない。
