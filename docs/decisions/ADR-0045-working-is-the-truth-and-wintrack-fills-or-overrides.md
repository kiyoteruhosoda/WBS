# ADR-0045: Working（手の打刻）が正。WinTrack の自動の打刻は「埋める」か「上書き」

- 状態: 承認
- 日付: 2026-10-13
- 関連: task #386（WBS 側）・#377（WinTrack）、取り決め `CONTRACT.md` の「改訂 2026-10-13（2）」、
  ADR-0042（自動の打刻の受け口。一部をこの ADR で置き換える）・ADR-0043（規則。1 を置き換える）・ADR-0018（Start の `at`）

## 背景

持ち主の決定（2026-10-13）: **Working（手の打刻）が正。** WinTrack は「始め忘れ」と「例外作業」だけを受け持つ。
既定のタスクは規則の一番下の「それ以外すべて」、例外はアプリ名か表題の語を指定した規則に当たった作業。
ADR-0042 の「重なれば丸ごと断る（overlap）」では、Working と少しでも重なる区間がすべて落ちる。

## 決定

### 1. 規則の「それ以外すべて」（ADR-0043 の決定 1 を置き換える）

- 両方空の規則を利用者ごとに **1 つまで**作れる（2 つ目・直して 2 つ目にするのは 422）。
- `position` に関係なく**いつも最後**に当てる。`GET /api/tracking-rules` と画面の一覧は最後に置いて返す。
  並べ替えでも最後のまま。画面では一番下に固定し「それ以外すべて」と出す（上下のボタンは出さない）。

### 2. `POST /api/time-entries/auto` の `mode`

- `fill`（既定）: ほかの打刻（手・自動・走っている打刻。走っている打刻は始まり〜∞）に覆われていない部分だけを
  打刻にする。空きの数だけできる。空きが無ければ `covered`（エラーではない）。
- `override`（例外作業）: 手の打刻（`auto` 以外）のその時間を切り抜いて作る。
  - 片側に掛かれば縮める・中に収まれば消す・またげば前後の 2 本に分ける（後ろは `source=split`、タスク・メモは同じ）
  - 走っている打刻が区間より前に始まっていれば区間の始まりで閉じ、区間の終わりから同じタスクで走らせ直す
    （`source=split`）。区間の中で始まっていれば始まりを区間の終わりへずらす
  - ほかの `auto` の打刻と重なれば `overlap`。区間か、切り抜く手の打刻が締めた期間に掛かれば `closed`（何も変えない）
- 応答は `entry`（1 つ）を **`entries`（配列）**に替えた。作らなかったときは `[]`。打刻の応答に `auto_mode` を足した。
- 判定の順: 送り直し → 範囲・タスク・`mode`（`invalid`、知らない `mode` は `unknown_mode`）→ 締め → 重なり／覆われ → 作る。
  断る理由を全部確かめてから書くので、断った区間は何も変えない。

### 3. 送り直しの見分けを「受け取りの控え」へ持ち替える（ADR-0042 の決定 2 を置き換える）

- `fill` は 1 つの `client_ref` から何本もできる（0 本のこともある）ので、`time_entries` の `(user_id, client_ref)` の
  一意をやめ（普通の索引にする）、**控えの表 `auto_time_entry_receipts`**（`user_id`・`client_ref`・`mode`・受け取った時刻。
  `(user_id, client_ref)` で一意）で見分ける。控えがあれば `duplicate` で、その `client_ref` の打刻（今残っているもの）を返す。
- 控えは**作ったときだけ**書く（`covered` や断った区間は書かない。送り直すと改めて判定する）。
- 自動の打刻には `auto_mode`（`fill` / `override`）を残す。移行の前からある自動の打刻は `fill` とみなし、控えも作る。

### 4. 切り抜いた手の打刻の記録

- 表 `time_entry_carvings` に、切り抜くたびに 1 行: 切り抜いた手の打刻の id・**切り抜く前の**始まり・終わり・タスク・
  出どころ・メモ・起きたこと（`shrunk_end` / `shrunk_start` / `split` / `removed` / `restarted`）・例外作業の区間と `client_ref`。
  打刻の id は外部キーにしない（消した打刻の id も残す）。ログにも `time_entries.auto.carved` を出す。
- 画面にはまだ出さない（締めの画面の作り直し #389 で、例外作業のセルから辿れるようにするかを決める）。

### 5. Start が `fill` を置き換える

- `POST /api/time-entries/start` の `at`（ADR-0018）以降に `fill` の自動の打刻があれば、Working が正なので置き換える:
  `at` 以降に始まるものは消し、`at` より前に始まるものは `at` で縮める。
- `at` 以降に `override` の自動の打刻があれば始めない（409）。手の打刻があれば今までどおり 409。

## 理由

- **控えの表を分ける**（採用）か、**打刻に断片の番号を足して `(user_id, client_ref, 番号)` で一意**にするか:
  断片の番号は「何本に分かれたか」を表に焼き付けるが、利用者が締めの画面で直す・消すと意味を失う。
  控えなら「受け取った」という事実だけを持ち、打刻はふつうに直せる。同時の送り直しも控えの一意で 1 つにまとまる。
  `covered` を控えないのは取り決めどおり（作っていないので、送り直しで改めて判定してよい）。
- **切り抜きの記録を表に残す**（採用）か、ログだけか: ログは日次で流れ、prod の journal はメモリだけのことがある。
  自動の打刻が手の打刻に勝つただ 1 つの場面なので、後から「元は何だったか」を引ける形で残す。
- **Start での置き換えを WBS でする**: WinTrack は 30 分ごとに送るので、開始を勧められて押したときには、その時間に
  `fill` が既に入っていることがある。Working が正なので、後から来た Working が勝つ。
  `override` は例外作業として持ち主が選んだものなので消さずに断り、WinTrack が `at` をずらす。

## 影響

- 移行 0019: 一意の索引を普通の索引へ、`auto_mode` 列・控えの表・切り抜きの表を足す。下げると、同じ `client_ref` の
  自動の打刻が 2 本以上あるときは一意の索引が作れずに失敗する。
- 応答の形が変わる（`entry` → `entries`）。WinTrack はこれがマージされてから新しい版を配る。
- 「それ以外すべて」は、タスクを消した・閉じたときの扱い（ADR-0043 の決定 3）も同じ（PC へは渡さない）。
