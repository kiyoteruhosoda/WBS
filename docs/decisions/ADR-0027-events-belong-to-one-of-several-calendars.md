# ADR-0027: 予定はカレンダー（複数）のどれか 1 つに属し、表示するカレンダーはサーバーに覚える

- 状態: 承認
- 日付: 2026-10-02

## 背景

持ち主の依頼（2026-10-01、task #191）: 「スケジュールでカレンダーを複数選びたい」。続けて
「毎回全部のカレンダー選ぶのは面倒」——選んだ状態は端末をまたいで覚え、名前付きの組み合わせで 1 回で
切り替えたい。休み（営業日・会社の公休・私の休み・日本の祝日）の 4 層を重ねて予定を立てる話も同じ課題に
積まれているが、量が大きいので PR を 2 本に割り、この ADR はその 1 本目（カレンダーの複数化・表示の選択・
表示の組み合わせ）を決める。休みの層は 2 本目で、この ADR を土台に足す。

これまで予定（ADR-0007・0009）は利用者に直接ぶら下がり、色は予定ごと（既定なら結んだタスクのカテゴリの色）だった。

## 決定

- 表 **`calendars`**（利用者ごと。名前・色・並び順・表示するか `is_visible`・既定か `is_default`・種類 `kind`）。
  色は予定と同じ色の名前（`EventColorKey`）。種類はいまは `EVENTS`（予定を入れるカレンダー）だけで、
  休みの層は 2 本目でここに種類を足す（表示の選択と組み合わせを 1 つの一覧で扱うため）。
- **予定はどれか 1 つのカレンダーに属する**（`calendar_events.calendar_id`、必須）。移行 `0009` で利用者ごとに
  既定のカレンダー「予定」を作り、**既存の予定はすべてそこへ入れる**。移行の後に来た利用者には、初めて要るとき
  （一覧・予定を作る）に作る。
  - 作るときに省けば既定のカレンダー。直すとき（すべて・単発）に省けば今のまま。「この回だけ」「これ以降」は
    省けば元の系列のものを引き継ぐ。他人のカレンダーは 404。
  - 画面は、既定のカレンダーを隠しているときは表示の先頭のカレンダーへ入れる（作った予定が見えなくならないように）。
- **予定の色**: 予定の色が既定ならカレンダーの色、それも既定なら結んだタスクのカテゴリの色、それも無ければ
  標準の色。回の一覧（`/calendar/occurrences`）に `calendar_id` と `calendar_color_key` を載せ、カレンダー・
  「今日」・締めの画面が同じ決め方で塗る。
- **表示の選択はサーバーに覚える**（`calendars.is_visible`。端末をまたいで同じ）。既定は全部オン、新しく作った
  カレンダーも最初からオン。`PUT /api/calendars/visibility` で表示にするものをまとめて置き換える（1 つの
  切り替えも「すべて」も同じ口）。
- **表示の組み合わせ**: 表 `calendar_view_presets`（名前 ＋ 表示にするカレンダーの id の JSON）。当てる
  （`POST /api/calendar-view-presets/{id}/apply`）と入っているカレンダーだけが表示になる。消したカレンダーの
  id は組み合わせから外す。画面ではカレンダーの一覧の上に並べ、今の表示と同じものを強調する。
- **選択が効くのはカレンダーの画面だけ**。「今日」の画面・締めの予定の列・分類（ADR-0025）・打刻の既定のタスク
  （ADR-0008）は選択に関係なく全部のカレンダーを見る（隠したカレンダーの予定も仕事としては残るため。持ち主に
  案を出して異論なし）。絞りは画面で行い、API の回の一覧は全部を返す。
- **消す**: 既定のカレンダーは消せない（409）。ほかを消すと、中の予定は既定のカレンダーへ移る（予定は消さない。
  移した予定は版が 1 つ進む）。

## 理由

- 表示の状態をカレンダーの行に持つのは Google カレンダーと同じ形で、「新しいカレンダーは最初からオン」
  「端末をまたいで同じ」がそのまま満たせる。利用者の設定に id の一覧として別に持つと、新しいカレンダーを
  足すたびに一覧へ足し忘れる道ができる。
- 組み合わせは「表示にするもの」の一覧で持つ（「隠すもの」ではなく）。後から足したカレンダーは、組み合わせを
  当てたときに隠れる。「計画 = 全部」のような組み合わせは「すべて表示」の切り替えで足りる。
- 既定のカレンダーへ入れる移行にしたのは、`calendar_id` を必須にして「どのカレンダーにも属さない予定」を
  作らないため（表示の選択で消えたり出たりする予定の扱いを 1 通りにする）。
- 消すときに予定を消さないのは、カレンダーを畳む操作と予定を捨てる操作を分けるため（捨てたければ予定を消す）。

## 影響

- 移行 `0009`（`down_revision` は `0008`）。`calendar_events` は SQLite で作り直すので、消した予定の id を
  使い回さない印（`sqlite_autoincrement` と採番の最大）を作り直しの前後で保つ。
- 予定の API の入出力に `calendar_id` が増える（省けば今までどおり）。回の一覧に `calendar_id` /
  `calendar_color_key`。
- 2 本目（休みの層・営業日の判定・重ねの塗り・休みの日の知らせ・ガント）は、`calendars.kind` に休みの種類を
  足し、表示の選択と組み合わせをそのまま使う。
