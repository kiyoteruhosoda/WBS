# ADR-0016: 締めの画面は予定と打刻を日ごとに左右へ並べ、期間を横に送って一度に見せる

- 状態: 承認
- 日付: 2026-10-01
- 関連: task #161（締め）の第 2 段・#163（締めの規則、決定済み）・ADR-0012（締めの表と API）・ADR-0008（打刻）・
  ADR-0013（カレンダーの画面）・ADR-0015（「今日」の画面）

## 背景

普段の記録は Start / Stop だけにした（ADR-0008）。その代わり、月 2 回の締めで**楽に直せること**が要る（持ち主の
指定）。API は ADR-0012 で揃った（画面 1 枚分・確定・開け直し・手で足す・分ける・つなぐ・まとめて振る・予定の回から
作る）。この段で画面 `/closing` を作る。決めることは、期間（最大 16 日）の見せ方、週表示の部品をどこまで流用するか、
打刻の操作の当て方、気付かせる物と確定の断りの見せ方、全画面の上部の知らせ。

## 決定

### 見せ方

- 時間グリッドは週表示と同じ 1px = 1 分。**各日の列を左（予定）と右（打刻）の 2 本に分ける。**
- **期間の全日を横に並べ、入らなければ横に送る**（1 日の列は最小 156px。見出しは上、時刻の列は左に貼り付く）。
  週ごとに送る形にしなかった。期間（1〜15 日 / 16 日〜末日）は週の区切りと合わないので、週で切ると 3 枚に割れ、
  月曜始まりの週の途中で期間が終わる。気付かせる物の一覧から飛ぶとき（`scrollIntoView`）も、送る単位が無い方が
  素直に届く。開いたときは 8:00 を上端にする。
- 期間は URL のクエリ `/closing?period=<初日>` で持つ。指定が無ければ、いちばん古い未確定の期間（無ければ今の期間）。
  前後の期間のボタンと、未確定の期間（＋今の期間）の選択肢で選ぶ。今の期間より先へは進めない。
- 終日の回は出さない（作業の時間ではない。ADR-0014 の数え方と同じ）。

### 週表示の部品の流用

- **純関数を流用し、`WeekView` 自体は使わない。** `WeekView` は予定の回（`DaySegment`）だけを描く作りで、終日の帯・
  過去の影・期限のチップを持ち、列を 2 本に割る口が無い。口を足すより、締めの格子（`components/closing/ClosingGrid.tsx`）
  を別に置き、計算は共有する。
  - 配置 `layoutTimedSegments` は区間の型について一般化した（`TimedSpan`。既定は `DaySegment` のままで、
    呼び手の書き換えは要らない）。打刻の区間（`closing/closingBoard.ts` の `EntrySegment`）をそのまま渡せる。
  - ドラッグの判定（8px・300ms 長押し・端のつかみ・自動スクロール）は `weekGestures` の `decideGesture` /
    `resizeEdgeAt` / `autoScrollDelta`、時刻の計算は `moveTiming` / `resizeTiming` をそのまま使う。
    `moveTiming` / `resizeTiming` には刻みと最短の長さの指定（`SnapOptions`。省けば今までどおり 15 分）を足した。
  - ポインタの追跡は `useWeekDrag` と同じ形の `components/closing/useClosingDrag.ts`（相手は右の打刻の列だけ。
    横の自動スクロールも足した）。
- 予定の色（タスクのカテゴリの色）・パレットはカレンダーのものを使う。

### 打刻の操作

| 操作 | 当て方 | 口 |
|---|---|---|
| 選ぶ | 押すたびに選択に足す・外す（複数選べる。指でも同じ）。空き時間を押すと選択を解除 | — |
| 動かす・伸ばす | 引く・上端 / 下端を引く。**15 分刻み、Shift を押している間は 1 分刻み** | `PATCH /time-entries/{id}` |
| 分ける | 「分ける」を押して、打刻の分けたい位置を押す（同じ刻み。位置に破線を出す） | `POST .../{id}/split` |
| つなぐ | 2 本以上を選んで「つなぐ」 | `POST .../merge` |
| 消す | 選んで「消す」（確認あり） | `DELETE` を 1 本ずつ |
| 足す | 右の列の空き時間を引く（指は長押ししてから引く）。作るのは未割当 | `POST /time-entries` |
| 時刻を直す | 1 本を選んで「時刻を直す」かダブルクリック。分単位の入力。**触らなかった時刻は秒まで元のまま送る** | `PATCH` |
| 予定どおり | 左の予定の回を押して「予定どおり（打刻にする）」の 1 操作。**その時間に掛かる打刻があれば警告を出す**（作ることは止めない）。終わっていない回は押せない | `POST .../from-occurrence` |
| タスクを振る | 選んで「タスクを振る」。候補は**同じ時間の予定の回のタスクを重なりの長い順に先頭**、続いて未完了のタスクを題名の順。「未割当に戻す」もある | `POST .../assign` |

- 打刻は秒まで持つ。動かしたら長さ（秒）はそのまま、伸ばしたら動かした側の端だけが変わる（反対の端の秒は残る）。
- 走っている打刻は動かさない・伸ばさない・つながない（終わりが決まっていない。止めるのは上部の打刻ボタン）。選ぶ・
  分ける・タスクを振るはできる。
- 書き込みは 1 つずつ。書いたら画面 1 枚分・打刻（上部のボタン）・「今日」の要約を読み直す。打刻ボタン側の書き込み
  （`timer/useTimer.ts`）も締めの画面を読み直させる。
- カレンダーと同じく、操作は「呼び出しのデータ」（`closing/closingRequests.ts`）に直してから 1 か所で送る。
  元に戻す・やり直しは入れていない（確定の前ならいつでも直せ、確定後は開け直せる）。

### 気付かせる物・合計・確定

- 一覧（右）に止め忘れ・重なり・未割当・打刻の無い予定を出し、数をバッジで。**確定を止める未割当を先に**並べる。
  押すとその打刻を選んで格子を送り、しばらく破線で囲む。打刻の無い予定なら、その回へ送って「予定どおり」の
  メニューを開く。格子でも、未割当は斜線、止め忘れは赤枠、重なりは橙枠、打刻の無い予定は赤い破線で描く。
- 「未割当を選ぶ」で未割当の打刻をまとめて選べる（そのまま「タスクを振る」へ）。
- 合計の表は行がタスク（合計の多い順、未割当は最後）、列が日。**表示は 15 分単位**（#163）、数字に重ねると秒までの長さ。
- 確定で断られた理由（409 / 422）は英語の `detail` を文で見分けて日本語にする。未割当・走っている打刻で断られたら、
  `detail` の id の打刻を選んで格子を送る。
- 確定済みの期間は読み取り専用（ドラッグ・操作のボタンを出さない）。「開け直す」は確認ダイアログを挟む。

### 上部の知らせ

- 全画面の `Layout` の本文の上端に「未確定の締めの期間があります（n 件。いちばん古いのは …）」を出す
  （`components/closing/ClosingNotice.tsx`、`GET /api/closing-periods/pending`）。押すとその期間の締めの画面へ。
  締めの画面の上では出さない。上部の帯（打刻ボタンの並び）には足さない（スマホ幅で場所が無い。ADR-0008）。

## 理由

- **2 本に分けた**: 予定と打刻を同じ列に重ねると、どちらを掴んだのか分からず、予定を動かしてしまう事故が起きる。
  左右に分ければ「予定どおりか」が横を見るだけで分かり、ドラッグの相手も右だけに絞れる。
- **押すたびに足す選択にした**: Ctrl / Shift を押しながらの選択は指で使えない。締めは「未割当をまとめて振る」が
  主な仕事なので、複数選びが既定の方が手数が少ない。
- **Shift で 1 分刻み**: 普段は 15 分で十分だが、打刻は秒まで持つので、隣と隙間なく合わせたいときの逃げ道が要る。
  それでも合わないときは「時刻を直す」で分単位に入れられる。
- **予定どおりで重なりを止めない**: 打刻が予定の一部だけに掛かっていることはよくある（会議の後半だけ別のことを
  していた等）。止めると先に打刻を消す手間が増える。作った後は重なりとして一覧に出るので、気付ける。

## 影響

- `weekLayout.layoutTimedSegments` と `weekGestures.moveTiming` / `resizeTiming` の型・引数が広がった（既定の振る舞いは
  変えていない）。
- 締めの画面の試験は、ほかと同じく純関数だけ（API の応答 → 表示の形、操作 → 呼び出し、断りの理由）。格子の
  ポインタ操作そのものは試験していない（jsdom を足していない。ADR-0013）。
- 未着手: 元に戻す、締めの期間の前後の日のはみ出し（期間の外の部分は出さない。隣の期間で直す）、キーボードだけでの
  ドラッグ相当の操作。
