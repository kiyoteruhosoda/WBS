# ADR-0055: プロジェクトは「いちばん上のプロジェクトのメンバー」で共有し、タスクに担当者を付ける

- 状態: 承認
- 日付: 2026-10-20
- 補足: 決定 6 の「いちばん上を新しく作る」は、作れる人を ADR-0065 で絞った（印のある人だけ）
- 関連: task #544（親 #542・目的 #522）、ADR-0024（プロジェクトの入れ子）、ADR-0003（定期照合）、
  Tracker の ADR-0053（タスクの写し）、task #539（WBS → Tracker 担当タスク）

## 背景

WBS は本来チームのプロジェクトの道具（#522 で持ち主が決めた）だが、データはすべて利用者ごと（`user_id`）に閉じていて、
自分以外の人のタスクを見ることも、タスクを人に割り当てることもできない。#539 で「自分の担当タスク」を Tracker へ渡すにも、
担当者が要る。

assay の名簿（`/admin/applications/self/users`）は識別子（`sub`）と「使ってよいか」しか返さず、名前もメールも無い。

## 決定（2026-10-20 に持ち主が選んだ）

1. **メンバーは「いちばん上のプロジェクト」（親の無いプロジェクト）に付ける。** その下のプロジェクト・タスク・マイルストーンは
   全部同じメンバーに見える。下のプロジェクトに別のメンバーは付けない（表 `project_members` の行は根にだけ置く）。
2. **役割は 2 つ**: `manager`（管理者）と `member`（メンバー）。
   - メンバー: その木のプロジェクト・タスク・マイルストーンを読み書きする（作る・直す・動かす・アーカイブ）
     （⚠ 動かすのは同じ木の中だけ。別の木へ移すのは元と先の両方の管理者だけ。ADR-0066）
   - 管理者: 加えて、メンバーの出し入れと役割の変更、いちばん上のプロジェクトを消す・他のプロジェクトの下へ移す
   - ⚠ 管理者は必ず 1 人以上残す（最後の管理者を外す・メンバーに下げるのは 409）
3. **プロジェクトに入っていないタスク・マイルストーン（未分類）は、作った人（`user_id`）だけのもの。**
4. **担当者** `tasks.assignee_user_id`（空可）。付けられるのは、そのタスクのいちばん上のプロジェクトのメンバー
   （未分類のタスクは作った本人だけ）。作るときに省けば作った人。一覧は担当者で絞れる（`assignee=me` / 利用者の id / `none`）。
   - メンバーから外れた人・別の木へ移ったタスクの担当は、**消さずに残す**（黙って書き換えない）。#539 は
     「担当が自分で、かつ自分に見えるタスク」だけを渡すので、外れた人の Tracker には出ない
5. **メンバーや担当者に選べる人は「WBS に 1 度でもログインした人」**（`users` の行）。招待の仕組みは作らない。
   assay の照合で結び付きが外れた人（`unknown`）と、止めた人（`is_active = false`）は候補に出さない。
   SSO（`AUTH_MODE=oidc`）では、assay の結び付きの無い行（初期ユーザー）も候補に出さない。
6. **プロジェクトを動かしたとき**
   - いちばん上のものを別の下へ移す: そのメンバーの行は消え、移った先の木のメンバーに見える（管理者だけができる）
   - 下のものを「いちばん上」へ出す: 元の木のメンバーをそのまま写す（見える人は変わらない）
   - いちばん上を新しく作る: 作った人が管理者
7. **今のデータの移し方**（移行 `0024`）: 今ある根のプロジェクトは作った人（`projects.user_id`）を管理者にする。
   今あるタスクの担当者は作った人にする（#539 で Tracker の選ぶ欄にそのまま出る）。消すもの・書き換えるものは無く、
   戻す（downgrade）と表と列が消えて元どおりになる。
8. 実績（`work_logs`）の合計・進捗率は、**タスクの全員ぶん**を積む（人ごとに分けない）。
9. **個人の画面（今日・ダッシュボード・週次ふりかえり）は今までどおり「作った人」で数える。** これらは #543 で外すので手を入れない。
   打刻・締め・規則・予定がタスクを指すときの確かめは、「自分に見えるタスク」に広がる（チームのタスクに打刻できる）。

## 理由

- 根だけに付ける案は、だれに見えるかが木 1 本で決まり、画面でも説明しやすい（どの段にも付けられる案は細かいが、
  「この子プロジェクトはだれに見えるのか」が上を辿らないと分からない）。役割を 3 つにする案（見るだけ）は、今の使い方に要らない。
- 担当者を空のままにする案は、#539 を入れた日に Tracker の選ぶ欄が空になる。今のタスクは全部その人のものなので、作った人を入れる。
- 招待（まだ入っていない人をメールで先に加える）は、assay のアプリへの割り当てと二重になる。nolumiatask と同じく、
  assay で使えるようにして 1 度入ってもらう形にそろえた。
- 外れた人の担当を自動で外す案は、外したことが残らず、戻したときに元へ戻らない。見える範囲で絞れば足りる。

## 影響

- タスク・プロジェクト・マイルストーン・依存の読み書きの確かめが「作った人か」から「見えるか」に替わる（倉庫の述語 1 か所）。
- カテゴリは今までどおり人ごと（他の人のタスクに付いたカテゴリは名前だけ出る）。
- 打刻まわり・予定まわりは Tracker・Scheduler へ移ったので、見える範囲が広がっても書き込みは移転モードの 409 のまま。
