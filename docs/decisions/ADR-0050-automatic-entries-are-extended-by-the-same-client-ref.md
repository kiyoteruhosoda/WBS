# ADR-0050: WinTrack の自動の打刻は、同じ client_ref で終わりを遅くして伸ばす

- 状態: 承認
- 日付: 2026-10-16
- 関連: task #400（WinTrack・WBS）・#377、ADR-0042（自動の打刻）・ADR-0045（Working が正）・ADR-0048（休み）、
  WinTrack の ADR-0008（30 分ごとのまとめ）

## 背景

WinTrack は、同じタスクが続く間は WBS の打刻を 1 件にするため、続かないと分かるまで送らなかった（WBS は同じ
`client_ref` を上書きしないので、送ってから伸ばせない）。そのため同じタスクを朝から続けると、昼になっても WBS に
何も届かない（持ち主の指摘、2026-10-16）。持ち主は「WBS に伸ばす口を足し、終わった時間帯ごとに送る」を選んだ。

## 決定

1. `POST /api/time-entries/auto` で、受け取り済みの `client_ref` が**始まり・タスク・`mode` が同じまま終わりだけ遅く**
   なって届いたら、**控えの終わりから新しい終わりまで（増えた分）だけ**を受けて打刻を伸ばす。結果は `extended`
   （その `client_ref` の打刻を全部返す）。
   - `fill`: 増えた分のうち、ほかの打刻に覆われていない部分。その `client_ref` の最後の打刻が控えの終わりで終わっていれば
     それを伸ばし、つながらなければ同じ `client_ref` で足す。全部覆われていても `extended`（何もしない）
   - `override`: 増えた分のうち、**ほかの自動の打刻を避けた部分**で、手の打刻を切り抜いて伸ばす・足す（切り抜く前の姿は
     今までどおり `time_entry_carvings` に残す）。新しく作る `override` と違い、ほかの自動の打刻と掛かっても断らない
     （その間に送った既定の打刻を壊さずに続ける）
   - 増えた分が確定済みの締めの期間に掛かれば `closed`（何も変えない）
2. それ以外の違い（始まり・タスク・`mode` が違う、終わりが遅くない）は今までどおり `duplicate`（上書きしない）。
3. 控え（`auto_time_entry_receipts`）に受け取った始まり・終わり・タスクを持つ（移行 0023）。それより前の控えは区間を
   持たないので伸ばさない（今までどおり `duplicate`）。

## 理由

- 打刻を差し替える（消して作り直す）と、その間に手で直した打刻や締めの画面での操作を壊す。増えた分だけを足せば、
  受け取り済みの部分には触れない。
- 始まりとタスクが同じことを条件にしたのは、WinTrack 側で中身を直した区間（別のタスクにした等）を、伸ばすことで
  黙って書き換えないため。

## 影響

- 古い WinTrack は同じ `client_ref` で終わりを遅くして送らないので、振る舞いは変わらない。
- `status` に `extended` が増える。WinTrack は `created` と同じく受け取られたとして扱う。
