# ADR-0024: プロジェクトは何段でも入れ子にでき、タスクとマイルストーンが属する

- 状態: 承認
- 日付: 2026-10-01

## 背景

持ち主の依頼（task #186・#187、2026-10-01）:

- 「タスクにプロジェクトという概念が欲しい。プロジェクトはサブプロジェクトも作れるようにして」（**nolumiatask 参照**）
- 「マイルストーンもプロジェクトごとで」

これまでタスクを束ねる軸はカテゴリ（平らな 1 段）とマイルストーン（全体で 1 列）しか無かった。
nolumiatask（kyon/nolumiatask）は同じ問題を先に解いている（ADR-0046 課題のモデルの形・ADR-0054
プロジェクトが設定を持つ・ADR-0052/0067/0080 画面）。どこを写して、どこを写さないかを決める。

## 決定

### 1. 表と列（移行 `0007`）

- 表 `projects`: 利用者ごと（`user_id`）。`parent_project_id` で**何段でも**入れ子（隣接リスト）。
  名前（200 字まで・前後の空白は落とす・空は 422）・色（`#rrggbb` か空）・説明・状態
  （`active` 進行中 / `archived` 保管。`String` で持ち、ネイティブ ENUM にしない）・兄弟の中の並び（`sort_order`）。
- `tasks.project_id` と `milestones.project_id`。**空 = 未分類**。
- **移行はプロジェクトを 1 つも作らない。** 既存のタスクとマイルストーンは未分類のまま。

### 2. 木の守り方

- **子孫は再帰 CTE で 1 回に引く**（`ProjectRepository.subtree_ids`。`UNION` なので万一の環でも止まる）。
  閉包テーブルは作らない（nolumiatask ADR-0046 の 1 と同じ判断。プロジェクトは数十のオーダー）。
- **環は作らせない。** 自分か自分の子孫の下へ移すのは 409（`ProjectCycleError`）。DB の制約では守れないので
  アプリ（`ProjectTree.would_cycle`）で断り、試験で固定する。
- 親を替える・並べ替えるのは `POST /api/projects/{id}/move`（`parent_project_id` と兄弟の中の `position`）
  だけ。`PUT` は名前・色・説明・状態だけを変える（環の判定を 1 か所に置く）。動かすと新旧の兄弟を
  0 から振り直す。
- 他人のプロジェクトは、見る・直す・動かす・親にする・タスクやマイルストーンを入れる・絞り込みに使う、
  のどれも 404（`owned_by` と同じ扱い）。CTE も子の側で持ち主を見る（他人の行が自分のプロジェクトの下を
  指していても辿らない）。

### 3. 絞り込みは子孫を含む

`project_id` を指すと、**そのプロジェクトと全部の子孫**のものが出る（nolumiatask と同じ）。
`unclassified=true` は未分類だけ。効く口:

- `GET /api/tasks`・`GET /api/gantt`・`GET /api/milestones`
- `GET /api/actuals/{tasks,gantt,periods,breakdown,export.csv}`。⚠ **絞るとタスク外の時間は数えない**
  （未割当の打刻・タスクに結ばない予定はどのプロジェクトにも属さない）。期間ごとの「タスク外の割合」は 0 になる。

画面はサイドバーの「表示するプロジェクト」で選ぶ（端末に覚える。`localStorage`。nolumiatask の
`useHomeProject` と同じ判断——端末ごとの好みで、失われても困らない）。従う画面は **タスク・ガント・
カレンダーの期限（タスクとマイルストーン）・実績・マイルストーン**。絞っている間は見出しの横に
「絞り込み中: 親 / 子」を出し、そこから外せる。⚠ **「今日」とカレンダーの予定そのものは絞らない**
（今日やることは全部のプロジェクトを跨ぐ。予定とタスクの選び方を束ねるのは #188・#189）。

### 4. 子タスクは親タスクと同じプロジェクト（アプリ側で揃える）

- 子タスクを作るとき、`project_id` を省けば親に揃う。親と違う値は 422。
- 子タスクの `project_id` を親と違う値へ変えるのは 422（子だけ別のプロジェクトにはできない）。
- **親（根のタスク）のプロジェクトを替えると子孫も一緒に移る**（`tasks.subtree_ids` を再帰 CTE で引いて一括で書く）。
- 親タスクを替える（`parent_task_id`）と、その枝は新しい親のプロジェクトへ移る。⚠ ついでに、**自分か自分の
  子孫を親にするのを 409** にし、親が自分のタスクであることを確かめるようにした（どちらも以前は見ていなかった。
  枝を引く CTE が成り立つための前提）。

**列は子にも持たせる**（根からの導出にしない）。絞り込みが `WHERE project_id IN (...)` の 1 本で済み、
実績の集計（`work_logs` → タスク → プロジェクト）も行ごとに辿らずに済む。代わりに「揃っていること」を
書き込みの側で守る——書く口はタスクのユースケースの 1 か所だけなので、ずれる経路は無い。

### 5. マイルストーンもプロジェクトに属する

- マイルストーンの `project_id`（空 = 未分類）。一覧の絞り込みはタスクと同じ（子孫を含む）。
- **タスクに付けられるのは、そのタスクのプロジェクトか、その祖先のプロジェクトのマイルストーンと、
  未分類のマイルストーン。** 親プロジェクトの節目（「案件 A のリリース」）は子プロジェクト（「設計」「実装」）の
  作業も締める。兄弟や子孫のプロジェクトのものは付かない（422）。nolumiatask にはマイルストーンが無いので、
  ここは WBS で決めた。
- **届かなくなったら外す。** タスクを別のプロジェクトへ移した・プロジェクトを別の枝へ動かした・マイルストーンを
  別のプロジェクトへ移した、のどれでも、付いていたマイルストーンへ届かなくなったタスクからは
  `milestone_id` を空にする（`ProjectMembership.detach_unreachable_milestones`）。断る形にしないのは、
  枝ごと動かすと子孫の何十件を手で外して回ることになるため。画面ではタスクのプロジェクトを替えた時点で
  選択を外し、「届かなくなったマイルストーンを外しました」と出す。
- 更新 API で `milestone_id: null` を送るとマイルストーンを外せるようにした（以前は null が「変えない」と
  読まれて外せなかった）。

### 6. 消す・保管する

- **消せるのは空のプロジェクトだけ**（子プロジェクト・消していないタスク・消していないマイルストーンが
  1 つでもあれば 409）。中のものを黙って未分類へ落とすと、何十件の所属が戻せない形で消える。片付けたい
  だけなら**保管**を使う（画面は 409 のときに「保管する」を出す）。消すときは行ごと消し、消したタスク・
  マイルストーンが指したままの値は空にする（id は使い回さない。`sqlite_autoincrement`）。
- **保管は自分の印だけ**（子へは書き写さない）。画面は「自分か祖先が保管」なら枝ごと選び先から外し、
  一覧では薄く出す（「保管したものも出す」で見える）。中のタスクと実績はそのまま読める。戻せば枝も戻る。
  ⚠ いま付いているプロジェクトは保管していても選び先に残す（保存しただけで外れないように）。

### 7. 実績のプロジェクト別（枝ごとの積み上げ）

`GET /api/actuals/breakdown?group_by=project`。カテゴリ別・マイルストーン別はそのまま、並べて足した。

- 絞らなければ**最上位のプロジェクトごと**に、その子孫の分まで積む。未分類は `none`、タスク外は `unassigned`。
- `project_id` を指せば、**その直下の子ごと**（孫より下も積む）と、そのプロジェクトに直に付いた分
  （`project:<id>` 自身）。サイドバーで選ぶと 1 段ずつ降りていける。
- 色はプロジェクトの色（無ければマイルストーンと同じ並び順の固定色）。

### 8. タスクの応答

`project_id` と、表示用の道筋 `project_path`（「親 / 子」。未分類は null）を足した。ガントの応答も同じ。
実績のカレンダー（#188）とタスクの選び方を束ねる（#189）はこれを使う。

## 理由 — nolumiatask から写したもの・写さなかったもの

| nolumiatask | WBS | 理由 |
|---|---|---|
| 多段は隣接リスト＋再帰 CTE（ADR-0046 の 1） | **写した** | 深さに決まりが無い・数十のオーダー・閉包テーブルは後から足せる |
| 環を禁じる（`MoveProjectUseCase`） | **写した**（409） | 環になると CTE も木の描画も止まらない |
| 一覧でプロジェクトを指すと子孫も含む | **写した** | 「案件 A」を開いて「設計」の作業が見えないのは困る |
| 一覧は親の下にぶら下げて見せ、親が見つからなければ最上位に置く（`ProjectsPage` の `toTree`） | **写した** | 深さが読める。壊れたデータで見失わない |
| 名前を後から直せる（`RenameProjectUseCase`） | **写した** | 名前は必ず後から変わる |
| key（URL 用の短い名前）を持たない（`0011_drop_project_key`） | **写した**（最初から持たない） | 作るたびに人が考える項目が増えるだけ。id で足りる |
| 最後に選んだプロジェクトを端末に覚える（`useHomeProject`・ADR-0054 の 3） | **形を変えて写した** | WBS では「どこを開くか」ではなく「どこで絞るか」として覚える |
| ステータス・種別・テンプレートをプロジェクトごとに持つ（ADR-0046 の 2・ADR-0054） | **写さない** | WBS のステータスは状態機械（`TaskStatus`）で全体共通。カテゴリも別の軸として残す |
| 課題番号をプロジェクト内の連番にする（ADR-0046 の 6） | **写さない** | WBS のタスクは id で指している。プロジェクトを移ると番号が変わる形は、移すのが普通の WBS に合わない |
| 削除は物理（ADR-0046 の 7） | **空のときだけ物理** | タスクとマイルストーンは論理削除のまま（既存の形）。中身ごと消す口は持たない |
| ツリーは長押しで動かす（ADR-0067） | **写さない** | プロジェクトは数十で、動かすのは稀。行の操作（上へ・下へ・親を替える）ならキーボードでも同じことができ、読む画面が動かす画面に見えない |
| 実施順のキーを文字列で持ち、比べ方を揃える（ADR-0080） | **写さない** | 兄弟の並びは整数で、動かすたびに振り直す。文字列キーの照合順序の問題（`utf8mb4_general_ci` で a と A が等しい）がそもそも起きない |
| 表示形式を役目で分ける（ADR-0052） | **写さない** | WBS は一覧・ガント・カレンダーが既に役目で分かれている。プロジェクトはそれらを横から絞る軸として足した |
| 権限（`project:manage`） | **写さない** | WBS は 1 人ぶんのデータ（`user_id` で分ける）で、役割の別が無い |

## 影響

- 移行 `0007`（`down_revision` は `0006`）。表 `projects` が増え、`tasks`・`milestones` に `project_id`。戻すと消える。
- 新しい API: `GET/POST /api/projects`・`GET/PUT/DELETE /api/projects/{id}`・`POST /api/projects/{id}/move`。
  既存の API は `project_id`（子孫を含む）と `unclassified` を受ける。
- タスクの更新で `milestone_id: null` は「外す」になった（以前は無視されていた）。タスクの編集画面は元から
  null を送っていたので、画面の振る舞いは「外したら外れる」に直る。
- タスクの親を自分の子孫へ付け替えるのは 409 になった。
- CSV の書き出しの列は変えていない（プロジェクトの列は足していない。外の工数の仕組みへ貼る形を崩さない）。
  絞り込みだけ効く。
- 後続: #188（実績のカレンダー）と #189（タスクの選び方・予定をプロジェクトで束ねる）は `project_id` /
  `project_path` と絞り込みの口を使う。ガントにはマイルストーンの表示がもともと無いので、ガントの
  マイルストーンを絞る話は表示を足すときに一緒にやる。
