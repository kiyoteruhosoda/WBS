# ADR-0065: いちばん上のプロジェクトを作れるのは、印のある人だけにする

- 状態: 承認
- 日付: 2026-10-30
- 関連: task #734（親 #725・点検 #728）、ADR-0055 決定 5・6（メンバー・作った人が管理者）、ADR-0058 決定 2（各人の休み）、
  ADR-0059 決定 2（人のカレンダー）

## 背景

ADR-0055 では、いちばん上のプロジェクト（根）を作った人がその木の管理者になり、管理者は「WBS に 1 度でもログインした人」を
メンバーに足せる（招待・承諾は無い）。管理者はメンバーの休み・その日の稼働時間を読み、書き換えられる（ADR-0058・0059）。
各人の休みは人に付く（チームをまたいで同じ）。

ところが根はだれでも作れるので、WBS に入れる人ならだれでも「自分の根を作る → 他人を足す → その人の休みを読む・書き換える」が
できた。書き換えはその人の別のチームの見込みにも効く（点検 #728 で stg で確かめた）。

## 決定（2026-10-30 に持ち主が選んだ）

1. **管理者ができることは変えない。** 同意なしにメンバーへ足すこと、メンバーの休み・稼働時間を読み書きすることは、
   管理者なら今のままできてよい。休みも人に 1 つのまま。
2. **いちばん上のプロジェクトを作れるのは、利用者に印（`users.can_create_projects`）のある人だけ。** 印の無い人が根を作ると 403。
   画面は印の無い人に「なし（最上位）」を選ばせず、「新しいプロジェクト」は入っている木の最初の根の下に作る。
3. 印の無い人も、メンバーになっている木の中では今までどおり下のプロジェクト・タスクを作れる。下のプロジェクトを根へ出すのも
   今までどおりだれでもできる（元の木のメンバーと役割をそのまま写すので、管理者は増えない）。
4. **印の付け外しは api の中の道具** `scripts/grant_project_creator.py <メール> [--revoke]`。相手は WBS に 1 度ログインした人だけ。
   外しても、もう作った根の管理者のまま。
5. **今のデータ**（移行 `0032`）: 今いちばん上のプロジェクトの管理者である人と、既定の利用者（id=1。SSO を使わない配備の 1 人）は
   印ありにする。ほかの人は印なし。戻すと列が消え、だれでも作れる元の形に戻る。

ADR-0055 決定 6 の「いちばん上を新しく作る: 作った人が管理者」は、作れる人を上のとおり絞ったうえで続ける。

## 理由

検討した案（2026-10-30、持ち主に出した比べ）:

| 案 | 採らなかった理由 |
|---|---|
| 足すときに本人の承諾を挟む（招待と承諾） | 持ち主の判断で、管理者が同意なしに足せるのは今のままでよい |
| 休みをチームごとに持つ | 同上。休みをチームごとに入れ直す手間も増える（ADR-0058 の理由） |
| 休みは本人だけが書き、チームには有無だけ見せる | 同上 |
| Assay にアプリごとの役を足して WBS へ渡す | Assay と WBS の両方を作り替える。nolumiatask・photonest など他のアプリは役を自分の DB に持ち、中の道具で付け外ししているので、それにそろえた |

管理者の権限はそのままでよいなら、残る穴は「だれでも管理者になれる」ことだけで、管理者になれる人を絞れば塞がる。

## 影響

- 移行 `0032`: `users.can_create_projects` を足す。`/api/auth/me` が `can_create_projects` を返す（画面がボタンを出し分ける）。
- 新しく WBS に入った人は、印を付けるまで自分の根を作れない。チームに入れてもらうか、印を付けてもらう（手順は OPERATIONS）。
