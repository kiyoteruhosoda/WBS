# ADR-0026: タスクの選び方はプロジェクトの木で束ね、締めの合計にプロジェクト別を足す

- 状態: 承認
- 日付: 2026-10-02
- 関連: task #189（この段）・#186（目的）・ADR-0024（プロジェクト）・ADR-0016（締めの画面）・ADR-0008（打刻）・
  ADR-0025（予定の分類「タスク」）

## 背景

持ち主は「1 日ごとの実績確認」を締めの画面（`/closing`）で見て、打刻にタスクを当てはめている（task #186）。
プロジェクト（ADR-0024）が入ってタスクが増え、同じ名前のタスクが別のプロジェクトにあり得るようになったのに、
タスクの選び方は 3 か所とも題名の平らな一覧だった。

- 締めの画面の「タスクを振る」: 同じ時間の予定のタスクを先頭に、残りは題名の順
- 上部の打刻ボタンのメニュー: 未完了のタスクを届いた順
- 予定の編集画面の「結ぶタスク」（ADR-0025）: 題名だけの入力欄

締めの合計の表もタスク別だけで、「どのプロジェクトに何時間」が読めなかった。

## 決定

### 1. 並べ方・束ね方・検索は 1 か所（`frontend/src/projects/taskPicker.ts`）

- **先頭の候補**（理由つき）→ **プロジェクトの木の順に、道筋（「親 / 子」）の見出しの下にタスク** → **未分類は最後**。
  束の中は題名の順。先頭に出したタスクは束に重ねて出さない。
- 先頭の候補は 2 種類。**同じ時間の予定のタスク**（重なりの長い順。終日の回は数えない）と、**直前に使ったタスク**
  （それより前に始まった打刻のタスクを新しい順に 3 つまで）。
  - 締めの画面: 選んだ打刻と重なる予定の回、選んだうち最も早い打刻より前の、期間の中の打刻。
  - 打刻ボタン: 開いた時刻の 1 分に掛かる今日の予定の回（「今日」の画面と同じ問い合わせの鍵）と、過去 7 日の打刻。
    サーバが Start の既定に使う順（いまの予定のタスク → 直前の打刻のタスク）と揃う。
- 出すのは未完了のタスク（消した・済み・やめたは出さない）。先頭の候補は済んだタスクでも出す（予定に結んだタスクを
  済ませた後で振ることはある）。フォームでいま選んでいるタスクは済んでいても残す（値が読めなくならない）。
- **検索はタスク名とプロジェクトの道筋の両方に当てる。** 空白で区切った語が全部どこかに入れば当たり。全角・半角と
  大文字・小文字を揃え（NFKC）、空白を詰めた形でも探す（「案件a」で「案件 A」に当たる）。
- 保管したプロジェクトのタスクも出す（未完了のタスクが残っているなら、打刻を振る先として要る）。

### 2. 見せ方は 2 つの部品、中身は同じ

- `components/TaskPicker.tsx`: 検索欄と一覧（見出しは貼り付く）。**締めの「タスクを振る」と打刻ボタン**が使う。
  打刻ボタンは `Menu` をやめて `Popover` にした（メニューの中の入力欄は、打った文字が頭文字で項目へ飛ぶ動きに取られる）。
  スマホ幅では「タスクを振る」は全画面のダイアログ。
- `components/TaskPickerField.tsx`: 同じ束ね方の入力欄（Autocomplete の `groupBy`）。**予定の編集画面の「結ぶタスク」**
  が使う。選んだ後は欄の下に道筋を出す（同じ名前のタスクを取り違えない）。以前はここに済んだタスクも出ていたが、
  他の 2 か所に揃えて未完了だけにした（いま結んでいるものは残る）。

### 3. サイドバーの範囲には「並べる順」だけ従う

- 範囲（ADR-0024 の 3）を選んでいれば、**範囲の中（子孫を含む）の束を先に、外の束を「表示中のプロジェクトの外」の
  区切りの後に**出す。**隠さない。** 確定は期間の打刻を全部見る（未割当が 1 本でもあれば 409）ので、範囲の外の
  タスクへ振れないと確定できない。打刻ボタンも、範囲の外のタスクで始めることは普通にある。
- **締めの画面のグリッド・気付かせる物・確定は範囲に依らず全部。** 範囲で打刻を隠すと、未割当を見落としたまま
  「確定できない」理由が見えなくなる。同じ理由で、締めの画面には「絞り込み中」の印を出さない（何かが隠れていると
  読めてしまう）。
- 範囲に従うのは、下の合計の表の「プロジェクト別」だけ（4）。

### 4. 締めの合計の表に「プロジェクト別」

- 表の上で「タスク別 / プロジェクト別」を切り替える（端末に覚える。`localStorage`。失われても困らない）。
- 積み方は実績のプロジェクト別（ADR-0024 の 7）と同じ:
  - 範囲が全部: **最上位のプロジェクトごとに子孫の分まで積む**。続けて未分類・未割当。
  - 範囲がプロジェクト: **そのプロジェクトに直に付いた分**（「名前（直接）」）と**直下の子ごと**（孫より下も積む）。
  - 範囲が未分類: 未分類の行。
  - ⚠ 実績の画面と違って、**範囲の外は捨てずに 1 行（「表示中のプロジェクトの外」）にまとめる**。締めは期間の打刻を
    全部確定するので、日の合計はタスク別の表と同じでなければならない。未割当も別の行のまま残す（確定を止めるもの）。
- 並びはプロジェクトの木の順（期間を送っても同じ場所に出る）。直の分が先、未分類・範囲の外・未割当は後。
- サーバの「日ごと・タスクごとの合計」（`GET /api/closing-periods/{first_day}` の `daily_totals`）に、タスクの
  **いまの**プロジェクト `project_id` を足した（未割当・消えたタスク・未分類は null）。画面がタスクの一覧から引き直す形に
  しなかったのは、確定した後に消したタスクの分も、サーバが持つ所属で正しく数えるため（積み上げはプロジェクトの木を
  持っている画面がする）。確定で作る `work_logs` の形は変えていない。

## 影響

- 移行なし。`daily_totals` の行に `project_id` が増えた（足しただけ）。
- 打刻ボタンのタスクの選び方を開くと、今日の予定の回と過去 7 日の打刻を引く（開いたときだけ）。
- 予定の編集画面の「結ぶタスク」に済んだタスクが出なくなった（いま結んでいるものは残る）。
- #188（実績のカレンダー）でタスクを当てはめるときも `TaskPicker` と `assignHead`（締めの候補）を使える。
