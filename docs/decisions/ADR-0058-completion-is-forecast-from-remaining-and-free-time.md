# ADR-0058: 終わる見込みの日は、残りの時間を担当者の空きに積んで出す

- 状態: 承認
- 日付: 2026-10-20
- 関連: task #552（子 #553〜#556）、ADR-0010（進捗率と残）・ADR-0055（メンバーと担当者）・ADR-0029/0032（休みの 4 層）

## 背景

持ち主（2026-10-20）「ガントでいつ終わりそうかを、残時間とアサイン比率で出したい。アサインされている人の従事率、1 日の工数、
休みなどで、タスクの工数をいつ終わらせられるのか」。

今の WBS が持っているのは、タスクの計画（開始・期限）・残（ADR-0010）・担当者（ADR-0055）・依存（FS / SS / FF / SF とずれの日数）
だけで、**終わる見込みの日は出していない**。人が 1 日に使える時間も、休みも持っていない。休みの 4 層（ADR-0029）は人ごとの予定の
仕組みで、今は Scheduler へ移った（ADR-0054。WBS に残るのは移したときの写し）。

nolumiatask にも従事率（`engagement_rate`）があるが、あれは課題ごとの「その課題に割く時間の割合」。考え方は借りるが、連携はしない。

## 決定（4 点は 2026-10-20 に持ち主が選んだ。どれもおすすめの案）

### 1. 単位: 人の空きはメンバーに、タスクの割合は任意

- **メンバー（いちばん上のプロジェクトの `project_members` の行）に「1 日の工数」と「従事率」**を持たせる。
  - 1 日の工数 `daily_hours`（時間。0〜24、既定 8）
  - 従事率 `engagement_percent`（%。0〜100、既定 100）= その人がこのプロジェクトに割く割合
  - **その人がこのプロジェクトに 1 日に使える時間 = 1 日の工数 × 従事率**（例: 8 時間 × 50% = 4 時間）
  - 直せるのは、そのプロジェクトの管理者と本人
- **タスクに「アサイン比率」`allocation_percent`（%。1〜100、空可）**を持たせる。入れたタスクは、担当者の 1 日の空きのうち
  その割合で毎日進む（下の 3）。空なら順番に片付ける側に入る。
- 人が複数のプロジェクトに入っているとき、プロジェクトごとの空きは別々に数える（従事率の合計が 100% を超えても止めない。
  決めるのは管理者）。
- **未分類のタスク**（プロジェクトに入っていない。担当は作った人だけ）は、1 日 8 時間・従事率 100%・月〜金・チームの休日なしで数える。

### 2. 休みは WBS に持つ（Scheduler からは読まない）

- **チームの休日**: いちばん上のプロジェクトごとに、稼働する曜日（表 `team_workweeks`、行が無ければ月〜金）と休日の日付の一覧
  （表 `team_days_off`: 日付・名前）。日本の祝日は暦（`japanese_national_holidays`）から年ごとに入れられる。直せるのは管理者。
  下のプロジェクトは根の休日を使う（メンバーと同じく根にだけ置く）。
- **各人の休み**: 人ごとの休みの日付（表 `member_days_off`: 利用者・日付、終日）。**プロジェクトをまたいで同じ**（その人が居ない日）。
  入れられるのは本人と、その人が入っているプロジェクトの管理者。見えるのは同じプロジェクトのメンバーだけで、持つのは日付だけ
  （理由や予定の中身は持たない）。
- Scheduler の休みの層・私用の予定には触れない。**WBS と Scheduler の間に新しい線は引かない。**
- 半日の休みは持たない（要るなら後で「その日に使える時間」を足す）。

### 3. 同じ人の複数のタスク: 順に片付け、比率を入れたものだけ並行

担当者 × いちばん上のプロジェクトを 1 つの「枠」とし、今日から 1 日ずつ進める。

1. **その日に使える時間**: 稼働する曜日で、チームの休日でも本人の休みでもない日だけ `1 日の工数 × 従事率`。ほかの日は 0。
2. **始められるタスク**: 子を持たない（葉の）タスクで、担当者があり、残が 0 より大きく、計画の開始日を過ぎていて、依存を満たすもの。
   依存の「ずれ」は**暦の日数**。
   - FS: 先のタスクの見込みの終わりの翌日 ＋ ずれ から
   - SS: 先のタスクが始まった日（もう実績がある・作業中なら今日より前）＋ ずれ から
   - FF・SF は始めるのは止めず、終わりの日を「先の終わり（FF）／先の始まり（SF）＋ ずれ」より前にしない
   - 先のタスクが完了・中止・残 0 なら満たしている。先のタスクに見込みが出ないなら、後のタスクも見込みを出さない（「先のタスク待ち」）
3. **配り方**: その日の時間を、まず**アサイン比率のあるタスク**へ `比率 × その日の時間`（残まで。比率の合計が 100% を超えたら比で割る）。
   残った時間を、**比率の無いタスクへ順番に**全部回す（1 つ目が終われば同じ日のうちに次へ）。比率のあるタスクは、ほかが空いても
   比率より速くは進まない（nolumiatask の従事率と同じく「この割合で進む」）。
4. **順番**: 期限の早いもの（期限なしは後）→ 優先度の高いもの → 計画の開始日の早いもの → 番号。依存で待っているものは飛ばして次へ。
5. その日に残が 0 になった日が**見込みの終わり**、最初に時間が入った日が**見込みの始まり**。

- **今日を 1 日目に数える**（今日の分の時間も丸ごと使う）。「今日」は見ている人のタイムゾーン（`UserClock`）。
- 見込みの先は **3 年**まで。越えるものは「3 年より先」。
- **見込みを出さないもの**（理由を返す。画面は理由の短い言葉を出す）
  - 完了・中止・残 0 → 出さない（終わっている扱い）
  - 担当者なし → 「担当者なし」
  - 残が決まらない（残も見積も空）→ 「残が未入力」
  - 担当者の空きが無い（メンバーでない・1 日の工数か従事率が 0・稼働する曜日が無い）→ 「空きなし」
  - 先のタスクに見込みが出ない・依存が輪になっている → 「先のタスク待ち」
  - 3 年を越える → 「3 年より先」
- **子を持つタスク**は自分では時間を使わず、開いている子孫の葉の見込みのうちいちばん遅い日（始まりはいちばん早い日）。
  見込みの出ない葉が 1 つでもあれば、親も出さない（「見込めない子あり」）。親自身の残は数えない（ADR-0010 と同じ）。
- **期限を越える**: 見込みの終わりが期限より後。越えた日数（暦の日数）を返す。
- **マイルストーン**: そこに付いた開いているタスクの見込みの終わりのうち、いちばん遅い日。見込みの出ないタスクの数も返し、
  1 つでもあれば日付は「少なくとも」の意味で出す。期限より後なら期限を越える。

### 4. 計算し直す時機: その場で毎回

- 見込みは**保存しない**。ガントを開くたび（`GET /api/gantt` と `GET /api/milestones`）にサーバーで計算する。
  残・休み・従事率・比率・依存を直せば、次に読んだときに変わる。
- 計算は Domain の `CompletionForecaster`（`src/domain/services/completion_forecast.py`）1 か所。外のもの（DB・時計）に触れない。

### ガントの出し方（#556）

- 計画の帯はそのまま。その下に**見込みの帯**（始まり〜終わり。点線の枠）と、終わりの日に菱形の印。
- 期限を越えるものは、色（赤）に加えて**形と文字**で示す: 期限の日に縦の線、帯の右に「⚠ 期限 +4 日」。行の名前の横にも ⚠。
- 見込みの出ないものは、帯の右に理由の短い言葉（「担当者なし」など）。
- マイルストーンの行に、見込みの日と（越えるなら）「⚠ 期限 +N 日」。

## 理由

- **空きをメンバーに置く**のは、従事率は「その人がそのプロジェクトに割く割合」で、決めるのは管理者だから。タスクごとに全部入れる案
  （nolumiatask の形）は、タスクが多いと入れる手間が大きく、入れ忘れると計算できない。比率を任意にすれば、
  「このタスクは半分だけ」も表せる。
- **休みを WBS に持つ**のは、WBS はチームの道具で、Scheduler を使っていないメンバーにも休みが要るから。Scheduler から読む案は
  入れる場所が 1 つで済むが、休みの日付だけを渡す新しい線（機械の口・権限）が要り、私用の予定との境を新たに作ることになる。
  自分の休みを 2 か所に入れる手間は残る。
- **各人の休みをプロジェクトに付けない**のは、休みは「その人が居ない日」で、プロジェクトごとに入れ直す意味が無いから。
- **順に片付ける**のは、「どれが先に終わるか」が読め、期限の早いものから終わる見込みになるから。全部を並行に進める案は
  終わる日が揃って遅くなり、読みにくい。
- **その場で計算する**のは、直した値がすぐ見えるため（#556 の受け入れ条件 3）。データは小さく、保存すると古い見込みが残る。
- 依存のずれを暦の日数にしたのは、今まで画面にも計算にも使われていない値で、いちばん説明しやすいから。

## 影響

- 移行で `project_members.daily_hours`・`engagement_percent`、表 `team_workweeks`・`team_days_off`・`member_days_off`、
  `tasks.allocation_percent` を足す（#554、移行 `0026`）。今の行は既定（8 時間・100%・月〜金・休みなし・比率なし）になる。
- `GET /api/gantt`・タスクの一覧・マイルストーンの応答に見込みを足す（#555）。ガントは見込みの帯と期限超過の印を描く（#556）。
- 人の休みは同じプロジェクトのメンバーに日付だけ見える。
- 見込みは「今の残・今の空き」の読みで、過去の見込みとの比べ（いつから遅れ出したか）は持たない。要るなら保存の仕組みを後で足す。
