# ADR-0064: Tracker で締めた「タスクの無いプロジェクトの時間」を、プロジェクトの実績として受け取る

- 状態: 取り下げ（2026-10-29、持ち主の判断。移行 0031 で表を消した）
- 日付: 2026-10-29
- 関連: task #708（親 #706）、ADR-0056 決定 3（締めた時間の口）、ADR-0024（プロジェクトの積み上げ）、
  Tracker の ADR（タスクと記録に WBS のプロジェクトを持たせる。task #711）

## 背景

#706 で持ち主が「実績には WBS のプロジェクト（コード）が要る」「WBS のタスクではない仕事も、締めたら WBS のプロジェクトの工数として送る」
と決めた。Tracker の記録は、WBS のタスクの写しに結ぶもののほかに、Scheduler の仕事の予定から始めた「プロジェクトだけ」の記録がある。
今の締めの口（`PUT /api/machine/closed-periods/{初日}`）は `wbs_task_id` の行しか受け取らず、`work_logs.task_id` は必須。

## 決定

1. **締めの口の行は `wbs_task_id` か `wbs_project_id` のどちらか 1 つを持つ。** 両方・どちらも無い行は 422。
   `wbs_project_id` の行は新しい表 **`project_work_logs`**（利用者 × プロジェクト × 日 × 秒、`tracker_first_day`）に入れる。
2. 置き換え・取り消しの単位はタスクの行と同じ（利用者 × Tracker の締めの期間の初日）。送り直しは期間ごとまるごと置き換え、
   `DELETE` はタスクの行とプロジェクトの行を両方退ける（論理削除。`removed` は両方の数）。
3. **受け取るのは本人に見えるプロジェクトだけ**（ADR-0055 のメンバーの木）。無い・見えないものは受け取らず、
   応答の `unknown_project_ids` で返す（`unknown_task_ids` と同じ扱い）。保管したプロジェクトも見えていれば受け取る（過去の時間のため）。
4. 数える場所は、実績の見える化の**確定実績**（ADR-0017）: 期間の確定実績、プロジェクト別の積み上げ（そのプロジェクトを含む枝へ。
   親で絞れば子の枝へ）、書き出し（`task_id` が空で `project` の列に道筋）。カテゴリ・マイルストーン別では「分類なし」に入る。
   タスクごとの表とガントには出ない（タスクが無い）。「未分類」で絞ると数えない。
5. 受け取った時間のあるプロジェクトは消せない（中身があるのと同じ 409）。退けた行は、消すときに一緒に消す。
6. 書き出しの CSV の最後に `project`（プロジェクトの道筋）の列を足す。タスクの行にもタスクのプロジェクトの道筋を入れる。

## 理由

- `work_logs.task_id` を空にできるようにする案は、タスクの実績・進捗率・残の見直し・ガントなど `task_id` を前提にした読み手が多く、
  1 つの書き漏れでタスク外の時間がどこかのタスクに混ざる。別の表なら、数えたい場所にだけ足せる。
- 1 行に両方を持たせる案（タスクとプロジェクト）は、タスクのプロジェクトが動いたときに食い違う。タスクの行の行き先はタスクが決める。
- 見えないプロジェクトを受け取らないのは、だれのプロジェクトの工数に入るかがこの値だけで決まるため（タスクと違い、受け取った後に
  見えるかどうかで絞る場所が無い）。

## 影響

- 移行 0030 で表を足す（戻すと表が消える。Tracker が送り直せる）。
- 応答に `unknown_project_ids` が増える（Tracker は知らない項目を読み捨てる）。
- 書き出しの CSV の列が 1 つ増える（最後なので、列の位置で読む人の今までの列は変わらない）。
