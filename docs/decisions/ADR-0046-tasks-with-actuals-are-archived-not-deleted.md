# ADR-0046: 打刻や実績のあるタスクは消さずに「しまう」

- 状態: 承認
- 日付: 2026-10-13
- 用語: 画面では「しまう」を「**アーカイブ**」と呼ぶ（task #394。プロジェクトのアーカイブとそろえる）。口・列の名前（`archive`・`archived_at`）は変えない
- 関連: task #388（持ち主の要望）、ADR-0043（規則。タスクが使えないと PC へ渡さない）・ADR-0012（締め）

## 背景

タスクを画面から消す手段が無かった（`DELETE /api/tasks/{id}` はあったが画面は使っていない）。そのまま消すと、
打刻や締めた実績（`work_logs`）から名前が引けなくなり（論理削除のタスクは引かない）、締めた期間の表が「名前の無い行」になる。
WinTrack の規則が指すタスクを消すと、規則が宙に浮く。

## 決定

1. **打刻も確定した実績も無いタスクだけを消す**（今までの論理削除）。あれば `DELETE` は 409。
2. あれば**しまう**（`tasks.archived_at`、`POST /api/tasks/{id}/archive`、冪等）。しまったタスクは:
   - タスクの一覧・「今日」・ガント・WinTrack の付け替え先（`GET /api/tracking-rules/tasks`）・タスクの選択欄に出ない
   - 1 件の取得（`GET /api/tasks/{id}`）・打刻・実績・締めの表には名前ごと残る
   - それを指す WinTrack の規則は止まる（PC へ渡さない。画面では「使われていない」と出す）。新しく規則を向けることもできない
   - ダッシュボードの件数・期限切れ、ふりかえりの期限切れに数えない（今週完了・今週作成は事実なので数える）
3. 確認の窓のための `GET /api/tasks/{id}/removal`: 消すかしまうか・打刻の件数と時間・確定した実績の時間・
   規則の件数・できない理由（`running` = 計測中）を返す。
4. 計測中のタスクは消すこともしまうこともできない（409。先に止める）。
5. 子タスクは今までどおり残る（親を消しても・しまっても子は消えない）。

## 理由

- 「消す」と「しまう」を 1 つの `DELETE` にまとめて裏で振り分ける案は、呼んだ側が結果を取り違えうる。口を分け、
  画面は先に `removal` を読んでどちらのボタンを出すか決める。
- しまったタスクを戻す口・しまったタスクの一覧は、今回は作らない（要望に無い。要るなら次の課題）。
- 子タスクのある親を断る案は、今までの振る舞い（親を消しても子は残る）を変えるので採らない。

## 影響

- 移行 0020（`tasks.archived_at`）。
- `TaskRepository.find_all` はしまったタスクも返す（実績・進捗の積み上げ・名前の引き当てに使うため）。一覧に出すところで外す。
