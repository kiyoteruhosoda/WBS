# ADR-0032: 休みは 4 層に一本化し、古い営業日カレンダーを畳む

- 状態: 承認
- 日付: 2026-10-02

## 背景

ADR-0029 で休みを 4 つの層（営業日の曜日・会社の公休・私の休み・日本の祝日）で持つようにしたが、互換のために
古い営業日カレンダー（ADR-0009）の API・設定画面・予定の編集画面の「営業日シフトで使うカレンダー」を残していた。
繰り返しの規則が古いカレンダーを名指ししていると、その祝日が休みの日に足され、「祝日だけ飛ばす」も効いた。
曜日の休み（土日など）は、週末ごとに帯が並ぶのを避けて終日の帯に理由を出さず地の色だけにしていた。

持ち主の決定（task #191 のコメント、2026-10-02）:

1. 曜日の休みも終日の帯に理由を出す。出し方はほかの層と揃える。ただし週表示で終日の欄が毎週 1 段埋まるのを
   和らげる工夫は入れてよい。月表示も
2. 古い営業日カレンダーを片付けて 4 層に一本化する（API・設定画面のカード・編集画面の選択欄・ドメインの口）。
   規則の名指しは移行で外す（「名指しすると祝日が足される」効き目も消す）
3. 休みの日の知らせはタスクだけにする。予定（分類が予定）を休みの日に置いても知らせない

## 決定

- **営業日シフトは休みの 4 層だけで決まる。** ドメインの `BusinessCalendar` と `BusinessDayShiftService` の
  `BusinessCalendar` 受けをやめ、`BusinessDayShiftService` は `DayOffLayers` を受ける（「祝日のときだけ」の条件 =
  「休みとして数える」層の日に当たるとき、N 営業日 = `DayOffLayers.shift_business_days`）。`AdjustmentRule` から
  `calendar_id` を外し、「祝日だけ飛ばす」（`shift_on_holidays_only`）は無くなる。層の出どころを繋がないとき（試験）は
  月〜金・休みの日なし。
- **API**: `/api/business-calendars`（CRUD と祝日・日本の祝日の取り込み）と `GET /api/calendar/holidays` を消す。
  繰り返しの規則の `adjustment.calendar_id` は書かず、入力に残っていれば読み捨てる（古い画面の版から来うるため 422 に
  しない）。日本の祝日の暦（`japanese_national_holidays`）は「日本の祝日」の層の取り込みが使う。
- **移行 `0013`**: 古いカレンダーの祝日のうち「日本の祝日」の層に無い日を層へ写す（0010 の後に古い画面で足した日を
  落とさない。層の無い利用者には 0010 と同じ 4 層を作る）→ 規則の `adjustment.calendar_id` を外す → 表
  `business_calendar_holidays`・`business_calendars` を消す。下げると表を作り直し、層のある利用者ごとに営業日
  カレンダーを 1 つ作る（曜日 = 営業日の層、祝日 = 日本の祝日の層の日）。外した名指しは戻らない。
- **画面**: 設定の「営業日カレンダーと祝日」のカードと、編集画面の営業日カレンダーの選択欄を消す。選択欄の場所には
  「営業日は休みの層で決まる」の一文を置く。
- **曜日の休みの帯**: カレンダー（月・週・平日）と「今日」の終日の帯に、曜日の休みの理由を「週休」と出す（狭い列でも
  読める短さ。知らせの文では今までどおり「曜日の休み」）。
  ほかの層と同じく営業日の層の表示のチェックに従う。週末ごとの帯で欄が埋まらないよう:
  - 同じ日にほかの層の理由（祝日・公休・私の休み）が表示中なら、そちらの帯 1 つだけを出す（曜日の休みは足さない）
  - 帯は控えめ（`subtle`）に描く: 塗りつぶさず、層の色の細い縦線と灰色の文字だけ。地の色・日付の色は今のまま
    （土曜は青・日曜は赤・平日の休みは曜日の休みの色）
  - 週表示では、控えめな帯はその日の列の予定だけを 1 段下げる（名前のある休みは今までどおり全部の日を 1 段下げる）。
    週末に終日の予定が無ければ、終日の欄の高さは帯が無いときと同じ
  - ガントには出さない（列の見出しの線と名前は今までどおり、名前のある休みだけ）
- **休みの日の知らせはタスクだけ**: 知らせるのは、分類がタスクの予定（定常業務の回を含む）を休みの日に置いたとき
  （編集画面で保存・ドラッグで別の日へ）、「時間を取る」でタスクを休みの日へ落としたとき、タスクの開始・期限が
  休みの日のとき（タスクの編集画面の日付の下に「休みの日です（理由）」）。分類が予定のものは知らせない。
  ガントのタスクの期間の営業日の数はそのまま。

## 理由

- 2 つの仕組みが並ぶと「どちらの祝日で寄ったか」が読めない。名指しで祝日が足される効き目は層に写した日と重なるだけで、
  残すと古いカレンダーを消せない。移行で古いカレンダーの日を層へ寄せてから名指しを外せば、寄り方は変わらない
  （「祝日だけ飛ばす」を使っていた規則だけは曜日の休みも避けるようになる。使われ方は確かめていない）。
- 名指しの入力を 422 にせず読み捨てるのは、PWA の古い版がしばらく送りうるため。読み捨てても寄り方は層で決まる。
- 帯を控えめにし、その日の列だけを下げるのは、毎週末の帯で平日の終日の予定まで 1 段下がるのを避けるため。帯を
  出さない（地の色だけ）より、理由の読める出し方が持ち主の求め。
- 予定（会議など）を休みの日に置くのは意図してのことが多く、知らせは雑音になる。タスクは営業日で数える計画に響く。

## 影響

- ADR-0029 の「名指しの営業日カレンダーの祝日を足す」「営業日カレンダーの API と設定画面は残す」「曜日の休みは帯を
  出さず地の色だけ」「休みの日に置いたら知らせる」の項はこの ADR で置き換え。ADR-0009 の営業日カレンダーの表と API は廃止。
- 古い画面の版（PWA のキャッシュ）は `/api/business-calendars` を引くと 404 になる。予定の編集画面の選択欄が空になるだけで、
  保存はできる（名指しは読み捨て）。
