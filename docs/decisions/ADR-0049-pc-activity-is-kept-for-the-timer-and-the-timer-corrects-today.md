# ADR-0049: PC を使っていた時間は wbstimer のためだけに持ち、wbstimer は今日の打刻を Bearer で直す（重なる修正は断る）

- 状態: 承認
- 日付: 2026-10-15
- 関連: task #397（WBS 側）・#398（WinTrack 側）・#399（wbstimer 側）・目的 #396、取り決め `CONTRACT.md` の節 7・8（改訂 4）、
  ADR-0012（締め）・ADR-0018（打刻アプリの Bearer）・ADR-0048（休み）

## 背景

持ち主の要望: 「wbstimer（スマホ）で開始・終了を押したとき、PC で既に作業していたら『開始していますか？』と聞いて、
PC の記録の時刻から始めたい。終了も同じ」「その日の時刻くらいは補正したい」。PC が知っている「使っていた時間」を
WBS 経由でスマホへ渡し、スマホから今日の打刻を直せるようにする。

## 決定

1. PC を使っていた時間は、**日の表** `pc_activity_days`（利用者・送り手のタイムゾーンでの日付ごとに 1 行。その日の
   `[0:00, 翌 0:00)`（UTC）と、最後に受けた時刻 `updated_at`）と、**区間の表** `pc_activity_spans`（日の行を指す。
   `started_at`・`ended_at`）に持つ。表題やアプリ名は受け取らない。**打刻・実績・締めには使わない**（休み（ADR-0048）とは違い、
   実績の長さにも効かない）。
2. 口（どちらも Bearer 可、`AppOrWebUserDep`）:
   - `PUT /api/pc-activity/{日付}`（`time_zone` での日付）: その日の区間を**丸ごと置き換える**（送り直しても同じ。
     `[]` で全部消える）。区間はその日の中・重ならない・終わり > 始まり（違えば 422）。7 日より前・未来は打刻と同じ制限
     （未来は 60 秒まで今に寄せる）。1 日 500 区間まで。**確定済みの締めの期間の日でも受ける**。
     応答は `{date, spans, updated_at}`（`updated_at` は WBS が受けた時刻）
   - `GET /api/pc-activity?start=&end=`: `[start, end)` に掛かる区間を始まりの順に。`updated_at` は範囲に掛かる日のうち
     最後に受けた時刻（1 日も無ければ `null`）
3. **35 日より前に終わった日は、書くとき（PUT）にその利用者の分を区間ごと消す。** wbstimer が読むのは今日だけで、
   WinTrack が送るのも 7 日以内なので、長く持っても使い道が無い。消す仕事を別に回さない。
4. 打刻の**期間の一覧**（`GET /api/time-entries`）と **1 件の修正**（`PATCH /api/time-entries/{id}`）を
   `AppOrWebUserDep` にする（ADR-0018 の「Bearer は決めた口だけ」に足す）。形は今のまま。足す・消す・分割・結合・
   まとめて振る・予定の回から作る、は Cookie だけのまま。
5. **打刻の時刻を直す修正（`PATCH` で `started_at`・`ended_at` を送ったとき）は、ほかの自分の打刻と重なれば 409**
   （`detail` は `the time entry would overlap another time entry (ids=…)`）。Web（締めの画面・今日の画面）も wbstimer も同じ。
   走っている打刻は今まで続いているものとして見る。接するだけ（終わり＝次の始まり）は通す。時刻を送らない修正
   （タスク・メモだけ）は、すでに重なっている打刻でも通す。足す・分割・結合・自動の打刻の口は変えない。

## 理由

- 日の行を別に持つのは、`spans: []` を送ったあとも「その日は受けている」（`updated_at`）を返すため。区間の行だけだと、
  空の日は受けていない日と見分けられない。
- 日ごとの丸ごとの置き換えにしたのは、休み（ADR-0048）と同じく差分を送らせないため（送れなかった分は次の回に送るだけでよい）。
- 締めの期間で断らないのは、打刻を動かさない読み物だから。確定した日に PC の記録が遅れて届いても困らない。

## 影響

- 移行 0022（`pc_activity_days`・`pc_activity_spans`）。
- 打刻の修正は、確定済みの締めの期間に掛かれば 409（今まで）、ほかの打刻と重なれば 409（決定 5、2026-10-15 に持ち主が決めた）、
  時刻の不正は 422。ADR-0012 の「重なりは断らない」は締めの確定と足す口の話として残る（重なっている打刻は締めの画面で知らせる）。
  修正で新しく重ねることだけを断るので、重なりを直すときは重ならない時刻まで動かす（途中の重なったままの時刻へは動かせない）。
- 画面は 409 の理由を「ほかの打刻と時間が重なる」と日本語で出す（`closing.error.overlap`）。
