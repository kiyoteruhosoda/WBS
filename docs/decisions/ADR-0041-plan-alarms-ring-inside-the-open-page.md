# ADR-0041: ブラウザの通知が使えない端末では、開いている画面の中で予定を知らせる

- 状態: 承認
- 日付: 2026-10-07
- 関連: task #312、ADR-0021（予定の通知と `GET /api/calendar/alarms`・鳴らす規則）・ADR-0031（Web Push）・
  ADR-0039（端末に覚える好み）

## 文脈

持ち主の会社の PC は、管理者が Chrome の通知を止めている（アドレスバーにビルの印、通知の許可は「Not allowed」）。
Web Push（ADR-0031）は購読できず、Notification API も使えない。予定の通知が届くのは打刻アプリ（Android）か、
通知を許したブラウザだけで、仕事中に見ている PC では何も鳴らなかった。
持ち主の選択（2026-10-07）は「PC の画面の中で鳴らす」——タブを開いている間だけで、閉じていれば鳴らないのは承知の上。

## 決定

1. **サーバーは変えない。** 画面（`frontend/src/components/InPageAlarm.tsx`、ログインの内側の `Layout` に置く）が
   既存の `GET /api/calendar/alarms`（Cookie で読める。ADR-0021 §4）を 1 分ごとに「今 − 1 分」〜「今 + 20 分」で引く。
   表に戻ったとき・設定を入れたときもすぐ引く。引けなければ前の一覧のまま（先の 20 分を持っている）。
   間隔を 1 分の猶予と同じにしたのは、作ったばかりの予定・別の端末で直した予定でも、知らせる時刻が 1 分より先なら間に合うため。
2. **鳴らす規則は ADR-0021 と同じ**（`frontend/src/alarms/inPageAlarm.ts`）: `notify_at` より早くは鳴らさない、
   1 分までの遅れは鳴らす、それより遅れたものは鳴らさない。
3. **確かめるのは 1 秒ごと、拍は専用の Worker が打つ**（`frontend/src/alarms/browserAlarm.ts` の `startTicker`）。
   裏のタブではページのタイマーが間引かれ、裏に回って 5 分を過ぎると 1 分に 1 回まで落ちる（Chrome）。
   1 回の長い `setTimeout` や 1 分ごとの確かめでは 1 分の猶予を超えうる。専用の Worker のタイマーは間引かれないので、
   Worker（Blob の URL で作る小さな 1 行）が送る拍で確かめる。Worker が作れなければページのタイマーで代える。
4. **知らせ方**: 画面の上の中央に、予定の題名・「15 分後に開始」／「開始時刻です」・開始時刻（設定の 12/24 時間の表記）・
   場所を、「閉じる」を押すまで出す。同じ回の知らせ（15 → 5 → 1 分前）は新しいものに置き換える。音は WebAudio で
   作る呼び鈴（3 音を 3 回。音声ファイルを足さない）。画面を見ていない間（裏のタブ・別の窓が前）はタブの題名を
   「🔔 題名」と交互に点滅させる。
5. **タブを複数開いていても音は 1 回だけ。** 鳴らした通知の `id` を localStorage（`wbs.inPageAlarm.rung`、1 日で捨てる）に
   印として残し、読んで書くまでを Web Locks（`navigator.locks`）で 1 タブずつにする。最初に印を付けたタブだけが鳴らす。
   表示はどのタブにも出し、閉じたら BroadcastChannel でほかのタブの同じ知らせも閉じる。
6. **音を出せないタブは譲る。** ブラウザは画面を 1 度も押していないタブの音を止める（自動再生の制限）。押したときに
   音の準備をしておき、準備のできていないタブは 3 秒待ってから鳴らす役を取りに行く（出せるタブが先に取る）。どのタブも
   出せなければ、知らせの中に「音を出すには、画面を一度押してください」と出す。
7. **この端末で Web Push を受け取っているときは鳴らさない**（二重にしない）。サーバが送れる・このブラウザの購読が
   サーバの一覧にあり「予定の通知もこの端末へ」が入・「知らせるもの」の「予定の通知」が入、のすべてを満たすとき
   （`pushCoversAlarms`）。分からない間・取れないときは画面の中で鳴らす（鳴らないより二重の方がよい）。
8. **設定は端末ごと**: 設定の「端末への通知」に「画面の中で知らせる」（既定は入）。localStorage（`wbs.inPageAlarm`）に
   覚え、サーバには置かない（ADR-0039 の時刻の表記と同じ判断。失われても既定に戻るだけ）。

## 理由

- **サーバーを変えない**: 通知の一覧も規則も ADR-0021 で揃っていて、画面がアプリと同じ口を引けば足りる。
  サーバから押す作り（Server-Sent Events など）は、開いているタブとの接続を持ち続ける仕組みが新しく要る。
- **Worker の拍**: 裏のタブの間引きに強く、追加の依存も Vite の設定も要らない（Blob の URL）。
- **鍵は Web Locks、印は localStorage**: localStorage だけでは 2 つのタブが同時に「まだ鳴っていない」と読みうる。
  Web Locks は同じ出どころのタブの間で 1 つずつ通す。BroadcastChannel だけで譲り合う作りは、誰が鳴らすかの
  決め方（一番古いタブなど）を別に持つ必要がある。
- **表示は全部のタブ・音は 1 回**: 持ち主が見ているタブがどれかは分からない。音が重なるのは困るが、表示が各タブに
  出ても困らない。
- 採らなかった案: 音声ファイルを足す（Service Worker の殻の一覧と版が変わり、軽い音で足りる）。
  サーバに設定を置く（端末ごとの事情で決まる好みで、ほかの端末に効かせる意味が無い）。

## 影響

- **タブを閉じている・ブラウザを閉じている・PC が眠っている間は鳴らない。** 持ち主は承知の上。
- 画面を 1 度も押していないタブ（開き直した直後など）は音が出ない。表示と題名の点滅は出る。
- Chrome の省電力の設定などでタブが凍結される（Worker も止まる）と遅れる。表に戻れば、1 分の猶予の内なら鳴る。
- Web Push を受け取っている端末で、購読・設定を変えた直後は判断が古いことがある（設定画面の操作で引き直す）。
- WBS を開いている間は、タブごとに 1 分に 1 回 `/api/calendar/alarms`（先の 20 分。数件の小さな応答）を引く。
