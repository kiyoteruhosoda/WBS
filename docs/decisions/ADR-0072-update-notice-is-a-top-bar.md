# ADR-0072: 新しい版の知らせは、どの画面でもいちばん上の帯にする

- 状態: 承認（ADR-0028 決定 3 の「画面の下に出す」を置き換える）
- 日付: 2026-11-09
- 関連: task #938、雛形 fastapitemplate の ADR-0106（同じ形）

## 背景

新しい版が待機すると「新しいバージョンがあります [再読み込み]」を出す（ADR-0028 決定 3）。これまでは画面の下の
中央に浮かべていたが、本文に紛れて目立たない。雛形 fastapitemplate で「いちばん上の帯」に変え（ADR-0106）、
持ち主が本番で試して派生アプリへも広げることになった。

WBS のヘッダーと左のメニューはサインイン後の外枠（`Layout`）にしか無く、ログイン画面には無い。ヘッダーの中に
置くと、ログイン画面では知らせが出ない。

## 決定

1. 知らせは**画面のいちばん上に、横幅いっぱいの帯で**出す。主色（`ds.primary`）の地に白い字、ボタンは色を反転させる
   （白い地に主色の字）。押されるまで消さない（ADR-0028 のまま）。
2. 帯は `App.tsx` で `<BrowserRouter>`（画面）より前に置き、**どの画面にも**出す。`position: sticky; top: 0` で、
   下へ送っても上に残す。
3. サインイン後の画面では、ヘッダーと広い画面の左のメニュー（どちらも `position: sticky`）が帯の**真下に**付く。
   帯は自分の高さを `<html>` の CSS 変数 `--update-bar-height` で渡し（狭い画面で折り返すと高さが変わるので
   `ResizeObserver` で見張る。`src/pwa/updateBarHeight.ts`）、貼り付く部品は `top: var(--update-bar-height, 0px)`
   （`BELOW_UPDATE_BAR`）に付く。左のメニューの高さもその分だけ縮める。帯が消えたら変数を外す。
4. 帯の重なり順（z-index 1100）はヘッダー（10）より上、狭い画面のメニュー（MUI の Drawer、1200）とダイアログより下。
   メニューやダイアログを開いている間はそれだけを操作させるため。

## 理由

- **ヘッダーの中に入れない。** ログイン画面で出なくなる。帯をヘッダーの上の別の段にすれば、ヘッダーのある画面では
  ヘッダーと一体に見え、無い画面でも同じ位置に出る。
- **固定（`position: fixed`）にしない。** 本文の上に重なり、ヘッダーや本文の先頭を隠す。sticky なら場所を取るので
  何も隠さない。
- **位置を変数で渡す。** 帯はルーターの外、ヘッダーと左のメニューは `Layout` の中にあり、同じ箱に入れられない。
- 雛形（ADR-0106）と同じ形にそろえ、アプリを渡り歩いても同じ所に出るようにする。

## 影響

- ⚠ **貼り付く部品（`position: sticky; top: …`）を足すときは、`top` を `BELOW_UPDATE_BAR`（帯の下）からにする。**
  そうしないと、知らせが出ている間その部品が帯の下に潜る。
- 帯が出ている間は、画面の高さが帯の分だけ伸びる（帯は場所を取るため）。
