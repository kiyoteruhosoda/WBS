# ADR-0015: 「今日」の画面を 3 層にし、ダッシュボードを寄せる

- 状態: 承認
- 日付: 2026-10-01

## 背景

朝に開いて 1 画面で済ませたい（task #160）。これまでは「ダッシュボード」（`/`）と「今日のタスク」（`/today`）の
2 枚があり、どちらも `/api/dashboard/today` のタスクの束（期限切れ・今日・明日・進行中）を並べていた。
一方で、打刻（ADR-0008）・予定（ADR-0009・0013）・予定とタスクの結び付け（ADR-0014）が入り、「今日」に
要るものは **予定と打刻と、まだ時間を取っていないタスク** になった。ダッシュボードの「作業を記録」（作業ログを
直に足す）は、打刻を締めで確定して作業ログにする流れ（ADR-0008・0012）と二重になっていた。

## 決定

1. **「今日」を最初の画面（`/`）にし、3 層で並べる。** スマホ幅では上からこの順（優先順位）、広い画面は左に
   グリッド・右に残りを積む。
   1. **いま** — 走っている打刻（タスク・経過・開始時刻・停止）と今日の実績の合計。止まっていれば、いまの予定
      （無ければ次の予定）のタスクで始める口を大きく出す。その下に **今日の予定のグリッド**（週表示の部品
      `WeekView` を 1 日幅で使う）。**今日の打刻を帯にしてグリッドの右端に重ねる**（予定のブロックは列の 8 割
      までなので、予定と並んで見える）。予定のブロックに ▶ を置き、押すとそのタスクで Start（走っていれば
      切り替え）。タスクの無い予定には出さない。
   2. **まだ時間を取っていないタスク** — 今日やるべきタスクのうち予定で埋まっていないもの。押すと
      `/calendar?schedule_task=<id>`（ADR-0014 の「時間を取る」）。スマホ幅は 3 件まで出して残りは畳む。
   3. **今日の実績**（打刻の長さのタスク別）と **KPI**（全体の進捗・今週完了・期限超過）。
2. **要約の口 `GET /api/today` を足す。** 利用者のタイムゾーンの今日の日付・区切り（UTC）・今日に掛かる打刻・
   走っている打刻・実績（日をまたぐ打刻は今日の分だけ、走っている打刻は今まで。締めと同じ
   `allocate_by_local_day` で数える）・まだ予定を取っていないタスクを返す。**予定の回は含めない**——画面は
   要約の `date` を `/api/calendar/occurrences` に問う（回の形を 2 か所で持たない）。画面の「今日」も要約の
   `date` と `time_zone` を正にする。
3. 「今日やるべき」は **未着手・進行中** のうち、**期限切れ・今日か明日が期限・開始日を過ぎた・進行中** のもの
   （これまでの束の 4 つと同じ範囲。待機中は自分では進められないので外す。明日が期限のものは今日のうちに時間を
   取る）。「まだ予定を取っていない」は `unscheduled_hours` > 0。**残が決まらない（見積も残も無い）タスクは、
   予定を 1 つも取っていなければ数える**——数えないと、期限が今日なのに見積の無いタスクが画面から消える。
   並びは優先度の点の高い順 → 期限の近い順 → id。
4. **ダッシュボードの画面と `/api/dashboard/today` は外す。** KPI（`/api/dashboard/kpi`）は残し、「今日」の
   下に小さく出す。`/today` は `/` へ寄せる。近日締切の一覧（期限が先のもの）と「作業を記録」は持ち込まない
   （期限はカレンダーとタスクの一覧、実績は打刻 → 締め）。
5. 打刻の書き込み（Start・Stop・付け替え）は上部の打刻ボタンと共有する（`timer/useTimer.ts`）。**409 は
   「いまの状態では書き込めない」として一般に扱う**——押し直しを促さず、サーバの理由（`detail`）を添える。
   確定済みの締めの期間（ADR-0012）に限った文言にはしない。

## 理由

- 束を並べるだけの 2 枚は「何をいつやるか」に答えない。予定（いつ）と打刻（実際）を同じ時間軸に並べ、
  予定から直に打刻を始められれば、朝の確認と作業の開始が 1 枚で済む。
- 要約をサーバで作るのは「今日」の境目を利用者のタイムゾーンで切るため（`UserClock`）。画面で打刻を
  合計すると、日をまたぐ打刻と走っている打刻の数え方が締めとずれうる。予定の回まで要約に入れる案は、
  回の形（繰り返し・振替・閲覧者のゾーンへの投影）を 2 本の API で持つことになるので採らなかった。
- 週表示の部品を 1 日幅で使えば、ドラッグ以外の描き方（重なり・終日の帯・今の線・過ぎた影）がカレンダーと
  そろう。帯と ▶ は省ける口として足し、カレンダーの画面は変えない。

## 影響

- `/api/dashboard/today` を使っていた画面は無くなった（ほかの使い手は無い）。
- 「今日」の画面からは予定を動かさない（ドラッグ・作成は `/calendar`）。予定のブロックが 15 分のように短いと
  ▶ は押しにくいので、いまの予定・次の予定の Start を上に大きく出している。
- 締めの画面（task #161 の次の段）で打刻を直したら、要約（`['today']`）を読み直させること。
