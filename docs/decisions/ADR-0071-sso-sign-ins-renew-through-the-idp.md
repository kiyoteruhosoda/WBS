# ADR-0071: SSO で入ったログインはリフレッシュトークンを持たず、切れたら画面を出さずに IdP へ問い合わせる

- 状態: 承認
- 日付: 2026-11-05
- 関連: task #889（親 #875）、fastapitemplate の ADR-0104（task #888・見本）、assay（idp）の ADR-0076（`SILENT_AUTH_FRAME_ANCESTORS`）。ADR-0069 の決定 2・4・5・6・8 を置き換える（決定 1・3・7・9・10 は残る。決定 7 の「止める判定は更新の 1 点」は、下の決定 6 の続ける往復へ移る）

## 背景

assay のログイン状態は、結び付けの有無で長さが変わり、端末の登録を取り消すと終わる（task #875・#887・#872）。ところがこのアプリは SSO で入ったあと、自分でリフレッシュトークン（14 日・使うと延びる）を持つ（ADR-0069）。Cookie をまとめて盗まれると、assay のログイン状態が終わっても、このアプリのリフレッシュトークンから 14 日使われる。

雛形（fastapitemplate）は ADR-0104 で「SSO のログインは更新の札を持たず、切れたら見えない枠で `prompt=none`」に替えた。このアプリは雛形の子孫ではない（ADR-0069 で仕組みだけ写した）ので、考え方を同じにして、このアプリの作りに合わせて入れる。

## 決定

1. **リフレッシュトークンとログアウトの札を出さない。** 出すのはアクセストークン（`ACCESS_TOKEN_EXPIRES_SECONDS`。既定 5 分）だけ。⚠ **このアプリのログインは SSO だけ**（`AUTH_MODE=single_user` はトークンを使わない）なので、雛形のように「パスワードのログインには残す」ものが無い。**更新の口 `POST /api/auth/refresh` は外す**（404）。手元に残った古い札は、使えないうえに、入る・続けるたびに Cookie を落とす。
2. **ログインの控え（`refresh_sessions` の行）は残す。** 雛形は SSO のログインに控えを作らないが、このアプリは停止の通知・定期照合・ログアウト・設定の保存での出し直しを、控えの行を消す／見ることで効かせている（ADR-0003・ADR-0069 決定 7）。これを変えないために、行は「ログインの控え」として残し、振り替えの列（`current_jti`・`previous_jti`・`rotated_at`）だけを消す（移行 0036）。表の名前はそのまま。行の期限は 30 日で、続けるたびに延ばす。
3. **切れたら、画面が見えない枠（iframe）で `GET /api/auth/renew` を開く。** そこから IdP へ `prompt=none` で往復し（往復の `purpose` は `renew`。往復は今までどおり DB の行 `auth_login_transactions` に置く）、戻り（`/api/auth/callback`）は Cookie を載せて結果の頁 `GET /api/auth/renewed?result=renewed|declined|failed` へ送る。画面は枠の行き先（同じオリジン）を読む。枠の中でスクリプトは動かさない。
4. **続けるのは入り直しではない。** 手元に残った期限切れのアクセストークンから「誰の・どのログインか」（利用者と控えの番号）を往復に写し、**同じ人が戻ってきたときだけ**その控えを延ばして引き継ぐ（IdP 側のログイン `sid` は戻ってきたものへ付け替える）。読むのは署名・発行者・宛先・種類を確かめ、期限は 30 日まで見逃す。そのためアクセストークンの Cookie はトークンより長く（30 日）残す。控えが消えていれば（停止の通知・定期照合・ログアウト）、IdP がまだ入っていると答えたので新しい控えを作る。手元にトークンが無くても同じ。
5. **別の人が戻ってきたら続けない**（`declined`）。IdP の「入っていない・許可が無い」、利用者が止まっている・このアプリにまだ居ない（続ける往復では利用者を作らない）、入れる人の決まりに外れた、も `declined`。往復が壊れた・IdP と話せない・このブラウザが始めた往復でない・時間切れ（15 秒）は `failed`。どちらも画面はログイン画面を出す（行き先は今いる画面）。
6. **止める判定は続ける往復に集める。** アクセストークンの検証は今までどおり DB を引かない。止まる上限はアクセストークンの寿命（5 分）のまま。
7. **ログアウトは、手元のアクセストークン（切れていてもよい）が指す控えの行を消す。** ログアウトの札が無くなったため。ほかの端末は続く。
8. **書きかけは sessionStorage に書くたびに写す**（画面の `sessionDraft.ts`）。受信箱の手早い追加に使う。サインアウトで全部消す。
9. **枠に入れてよいのは自分のオリジンだけ。** `/renew`・続ける往復の戻り・結果の頁は `X-Frame-Options: SAMEORIGIN` と `frame-ancestors 'self'`。
10. **続ける往復はタブをまたいで 1 本ずつ**（Web Locks）。順番を待つ間にほかのタブが続けていれば（`/api/auth/me` が通れば）枠を開かない。サインアウトした印（`wbs.sso.signedOut`）があれば問い合わせない。断られたらこのタブの「試した」印を付け、ログイン画面の黙った確かめ（ADR-0062）を重ねない。サーバーに届かないときはログアウト扱いにしない（ADR-0069 決定 8 のまま）。
11. 停止の通知の再送を覚える長さは、控えを残す長さ（30 日）にする（14 日のままだと、それより古い通知の再送が、続けて残っている控えを落とす）。

### 雛形（ADR-0104）と変えたところ

| 雛形 | このアプリ | なぜ |
|---|---|---|
| パスワード・パスキーのログインには更新の札を残す | 更新の口ごと外す | ログインは SSO だけ |
| SSO のログインには控えを作らず、停止は止めた記録（`session_revocations`）で見る | 控えの行を残し、続けるたびに延ばす | 停止・照合・ログアウト・出し直しが控えの行で効いている（ADR-0069 の形を崩さない） |
| 引き継ぐのはロール・サインインした時刻・パスキーの印 | 引き継ぐのは控えの番号だけ | ロールも「入り直したばかり」の判定も無い |
| 往復は署名付きの Cookie | DB の行（`auth_login_transactions`）に `purpose`・続ける利用者と控えの番号を足す | 往復は前から DB の行 |
| 戻りで引き換え券をその場で換える | Cookie を直に載せる | 引き換え券を持たない（戻りがそのまま Cookie を載せる作り） |
| 画面の CSP に `frame-src` を足す | 足さない | 画面に CSP を付けていない（枠の行き先を止めるものが無い） |
| 401 のうち `authentication_required`・`invalid_token` だけ続ける | 401 なら続ける | 入口の 401（パスワード違いなど）が無い |
| `sessionEnded.ts` で知らせる | 今の `setUnauthorizedHandler` を使う | 同じ役の一本道が既にある |
| 続ける往復の成功を監査に積まない | アプリログ（`auth.sso.renewed` など）だけ | 監査ログの表が無い（ADR-0068 と同じ） |
| 続ける往復で利用者を作る・結び付ける | 作らない（`declined`） | 作るのはボタンで入るときだけにする（作る決まり ADR-0002 を 1 か所に保つ） |

## 理由

- **何を塞ぐか**: Cookie を盗まれても、5 分を過ぎると IdP のログイン状態（結び付け・端末の登録・取り消し）に従う。
- **iframe を主にする**: 画面が切り替わらず、書きかけも残る。結果は URL で渡す（`postMessage` だと結果の頁にスクリプトが要る）。
- **控えを残す**: 雛形の形（控え無し・止めた記録）へ寄せると、停止の通知と定期照合の作りを書き直すことになる。控えを残せば、消す側はそのままで、続ける往復が控えを延ばすだけで済む。

| 採らなかった案 | 捨てた理由 |
|---|---|
| リフレッシュトークンを短くする（1 時間など） | 盗まれてからその長さは使われる。IdP の取り消しも効かない |
| 全画面の往復だけにする | 5 分ごとに画面が切り替わり、書きかけが消える。予備として残す（ログイン画面の黙った確かめ） |
| 更新の口を残し、来た札を断るだけにする | 札を出す入口がもう無い。口を残すと、振り替えの作りと MariaDB の同時実行の試験を持ち続けることになる |
| 続けるたびに新しい控えを作る | 5 分ごとに行が増え、ログアウトや停止の通知が古い行しか消さない |

## 影響

- SSO のログインの長さは IdP のログイン状態で決まる。画面を閉じていた間に IdP のログイン状態が終わっていれば、開いた時点でログイン画面になる（今までは 14 日続いた）。
- 配った時点のログインはそのまま続く（控えの行は残る。手元のリフレッシュトークンは使えなくなるが、切れたら見えない枠で続ける）。
- 環境変数 `REFRESH_TOKEN_EXPIRES_SECONDS` は読まなくなった。CI の `refresh-on-mariadb`（振り替えの同時実行を MariaDB で流すジョブ）は外した（振り替えが無い）。
- IdP（assay）は `prompt=none` の往復を `*.nolumia.com` の枠の中で通す（idp の ADR-0076。本番の `SILENT_AUTH_FRAME_ANCESTORS`）。stg の画面は `http://localhost:18110` で開くので、枠の中の往復は止められ、ログイン画面の黙った確かめ（全画面）で入り直す。
- DBSC（task #887）の更新は要求を出したオリジン基準なので、assay 側の `allowed_refresh_initiators` が要る（#887 の持ち分）。
