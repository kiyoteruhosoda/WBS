# ADR-0075: 前段の 503（メンテナンス・停止）でアプリ内のメンテナンス画面に切り替える

- 状態: 承認
- 日付: 2026-11-20
- 課題: task #655（目的は #653「計画メンテナンス」）。雛形 fastapitemplate の ADR-0067（#664）と同じ振る舞い

## 背景

本番は `Recreate` で配るので、版を入れ替える間は数分止まる。deck はその間、公開ホストの前段（edge の nginx）に
メンテナンスを宣言させ（nolumiadeck ADR-0182）、edge はそのホストへの要求すべてに **503** を返す。
ブラウザの画面の移動には edge のメンテナンスのページ、それ以外（API の呼び出し）には JSON:

```json
{"error": "service_unavailable", "reason": "maintenance",
 "until": "2026-11-20T10:00:00Z", "message": "<理由>",
 "title": "<見出し>", "body": "<本文>"}
```

上流（このアプリ）が居ないだけのときは `reason: "stopped"`。

ところが画面は Service Worker が手元の殻（index.html）を返すので、edge のページは見えない。API が 503 で落ち、
各画面がばらばらに失敗を出すだけで、利用者には「壊れた」としか見えず、いつ戻るかも分からなかった。

## 決定

**API の通り道（`frontend/src/api/client.ts` の axios の応答の関所）で edge の 503 を見分け、アプリの画面を隠して
メンテナンスの画面を出す。1 分ごとに確かめ直し、開いたら同じ画面（同じ URL・入力の途中）へ戻る。**

- 見分け方（`frontend/src/pwa/maintenance.ts` の `outageFrom`）: 状態が 503 で、本文が JSON の
  `{"error": "service_unavailable", "reason": "maintenance" | "stopped"}` のときだけ。アプリ自身のエラー
  （`{"detail": …}`）や HTML・知らない `reason` の 503 は、今までどおりの失敗
- 見分けた呼び出しは状態を「閉じている」にしたうえで、今までどおり失敗として投げる（呼んだ側は止まる）。
  何か答えが返れば（成功）閉じていないと分かるので外す
- 画面（`frontend/src/components/MaintenanceScreen.tsx`）は `main.tsx` が**アプリとは別の root**に描き、
  アプリの root は `hidden` で隠すだけ（消さない）。見出し・本文は edge の `title`・`body`、無ければアプリの文。
  理由（`message`）と戻りの見込み（`until`。閲覧者の時間帯で、`UTC+9` の形の時差を付ける）は、あれば出す。
  文言はログインの外でも出すので `translate`（最後に使った言語）で描く
- 確かめ直しは、画面が出ている間 1 分ごとと、タブが手前に戻ったとき、「いま確かめる」で
  `GET /api/auth/config`（ログイン不要で軽い）を保存された答えを使わずに叩く。edge の 503 ならまだ閉じている
  （中身は新しい方に入れ替える）。**500 未満の答えはすべて「開いた」**（edge が通したということ）。
  届かない・別の 5xx は何も分からないので、そのまま次を待つ
- 開いたら、問い合わせ（React Query）をすべて取り直す（閉じている間に開いた画面は失敗しか持っていない）
- 閉じている間に開いた場合、`AuthProvider` は設定の失敗から「SSO なし」と決めつけず、待ちの表示のままにする
  （画面はメンテナンスの画面がかぶさっている）

## 理由

- **見分けを axios の関所 1 か所にする。** API の呼び出しはすべて `client` を通るので、画面ごとに 503 を受けると
  足すたびに書き漏れる
- **隠して、消さない。** メンテナンスを道（route）にすると戻り先を覚える必要があり、入力の途中も消える
- **確かめる先はログイン不要の口。** 雛形は「成功だけを開いた」としているが、このアプリの軽い口は認証つきが多く、
  401 を「分からない」にすると戻れない。edge は閉じている間どの道にも同じ 503 を返すので、500 未満なら開いている
- 遅れて読み込む部品（動的 import）は使っていないので、雛形の `vite:preloadError` の見張りは入れない

採らなかった案:

- **各画面・各フックで 503 を受ける** ——上のとおり書き漏れる
- **確かめ直しをやめて利用者の「再読み込み」だけにする** ——自動で戻ることを求められている

## 影響

- 依存は増えない
- 「オフライン」の帯（ADR-0028）は応答の無い失敗だけを数えるので、503 では出ない（今までどおり）
- deck の宣言が無い（edge が古い・宣言しない配り方）ときは何も変わらない
