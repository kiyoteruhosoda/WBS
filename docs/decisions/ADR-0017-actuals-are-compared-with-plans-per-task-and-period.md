# ADR-0017: 実績を計画・予定と並べる口と、「残を見直す」の判定

- 状態: 承認
- 日付: 2026-10-01
- 関連: task #162（実績の見える化）・#161 / ADR-0012（締め）・ADR-0016（締めの画面）・ADR-0010（残と進捗率）・
  ADR-0014（予定済みの時間）

## 背景

締め（ADR-0012）で確定した実績（`work_logs`）は、タスクの進捗率に入るだけで、計画（見積・残）や予定
（カレンダーの回）と見比べる場所が無かった。残は自動で減らさない決め（ADR-0010）なので、締めの後に
**残を手で見直してもらう**きっかけも要る。外の勤怠・工数の仕組みへ貼る書き出しも無い。

## 決定

### 口（`/api/actuals`）

| 口 | 中身 |
|---|---|
| `GET /tasks`（`review_only`） | タスクの応答（見積・予定済み・実績・残・進捗率。一覧と同じ値）に、実績の最初と最後の日・直近に確定した期間の実績・**残を見直してほしい理由**を足した行。直近に確定した期間も返す |
| `GET /gantt`（`from` / `to`） | タスクごとの実績の帯。最初と最後の日は全期間の `work_logs` から、日ごとの実績は問うた範囲だけ |
| `GET /periods`（`unit`・`from` / `to`） | 期間ごとの予定（タスクに結んだ / 結んでいない）・打刻（タスク / 未割当）・確定実績・差（打刻 − 予定）・タスク外の割合。締めの期間なら確定済みか |
| `GET /breakdown`（`unit`・`group_by`・`source`・`from` / `to`） | 期間ごとの時間をカテゴリ別・マイルストーン別に積み上げる |
| `GET /export.csv`（`from` / `to`・`source`） | 期間（締めの期間）× 日 × タスク × 時間の CSV（UTF-8、BOM 付き） |

- 単位（`unit`）は `closing`（締めの期間）/ `week`（月曜始まり）/ `month`。範囲を省くと今の期間で終わる 6 期間、
  端の期間は丸ごと含める。並べるのは 120 期間まで、書き出しは 366 日まで（超えると 422）。
- 日付はすべて利用者のタイムゾーン（`users.timezone`）。

### 3 つの時間をそろえる

予定・打刻・確定実績を、いったん（タスク, 利用者の日付）ごとの秒数（`DailyLedger`）にしてから期間・タスク・
グループで足し直す。

| 時間（`source`） | 数え方 |
|---|---|
| 予定（`planned`） | 予定の回（`OccurrenceSource`、閲覧者＝利用者のタイムゾーンへ投影）。**終日の回は数えない**（ADR-0014 と同じ）。回はその始まりの日に数え、日をまたいでも割らない。タスクに結んでいない回はタスク外 |
| 打刻（`tracked`） | 締めと同じ割り方（日をまたぐ打刻は利用者の 0:00 で割る。走っている打刻は今まで）。タスクが空・消えた・他人のものはタスク外 |
| 確定実績（`confirmed`） | `work_logs`（締めで作ったもの・手で書いたもの）。長さは `duration_seconds`、無ければ `hours` |

- **数えるのは本人のものだけ。** 予定・打刻は利用者で引き、`work_logs` は本人が書いた・本人のタスクの行に絞る
  （`WorkLogRepository.find_for_user`）。消したタスクの実績は数える（実績は残っているため）。
- 期間ごとの「実際の時間」の差は**打刻 − 予定**で出す（締め前の期間でも意味がある）。確定実績は並べて出すだけ。
- タスク外の割合は「タスク外 ÷ 全体」（0〜1）。分母が 0 なら null。

### 残を見直してほしいタスク（`remaining_review_reasons`）

対象は未完了の葉（DONE・CANCELLED・子を持つタスクは外す。親の残は子の積み上げ。ADR-0010）。

| 理由 | 判定 |
|---|---|
| `over_estimate` | 見積を超えた実績があり、残を手で入れていない（既定の残が 0 で 100% と出ている） |
| `no_remaining` | 未完了なのに残が 0（手で 0、または見積をちょうど使い切った） |
| `unknown_remaining` | 見積も残も無いのに実績がある（進捗率が出ない） |
| `stale_remaining` | 手で入れた残があり、**直近に確定した期間**でそのタスクの実績が増えたのに、その確定（`closed_at`）の後にタスクを直していない（`updated_at`） |

- 残を入れる（または完了にする）と `updated_at` が確定より後になり、どの理由も消える。「見直した」という
  印を別に持たない。
- 画面は `/actuals/review`（タスクの表を見直しが要るものだけに絞り、その場で残を入れる）。締めの画面からの
  導線はこのルートへ繋ぐ。

### 画面

- `/actuals`（タスク）・`/actuals/review`（残を見直す）・`/actuals/periods`・`/actuals/breakdown`・`/actuals/export`。
- ガントは計画の帯の下に、確定した実績の最初〜最後の日の細い帯と、実績のある日の塗りを重ねる。
- グラフは依存を足さず、MUI の箱と CSS で描く（積み上げの横棒・予定と打刻の対の横棒）。同じ数字を表でも出す。

## 理由

- **(タスク, 日) の帳簿にそろえる**: 予定・打刻・確定実績は持ち方（回・区間・日ごとの行）が違う。一度同じ形に
  すれば、期間・カテゴリ・マイルストーン・CSV のどれも同じ足し方で済み、期間の境目の扱いが食い違わない。
- **差を打刻で取る**: 確定実績は締めの後にしか無く、今の期間で 0 になる。予定と比べたいのは「実際に使った時間」
  なので、締め前でも数がある打刻にした。確定実績は書き出し・積み上げの既定に使う（外へ出すのは確定した数）。
- **「直した」を `updated_at` で見る**: 見直し済みの印を表に足すと、残の変更・完了・開け直しのたびに消し忘れが
  起きる。タスクを直した＝見た、と割り切れば列も移行も要らない。タスクの他の欄を直しただけでも消えるが、
  その時に残も目に入っている。
- **予定の回を割らない**: 予定は「その日に取った時間」で、日をまたぐ回はまれ。打刻と同じ割り方にすると、
  0:00 をまたぐ予定が前日の計画に半分残り、見た目と合わない。
- **CSV に BOM**: 表計算ソフトが UTF-8 と気付かず、タスク名が文字化けする。
- グラフの依存を足さなかったのは、lockfile を CI で作る手間（#15 のやり方）に見合う形が無いため。

## 影響

- `work_logs` を利用者で引く口（`find_for_user`）が増えた。索引は足していない（1 人分の行数が小さい前提）。
- `/actuals/tasks` はタスクの一覧と同じく、結ばれた予定を 365 日ぶん展開する（ADR-0014）。
- CSV の `hours` は小数 2 桁へ四捨五入、正確な長さは `seconds` 列。
- 締めの画面（ADR-0016）から `/actuals/review` への導線は別に足す。
