# ADR-0029: 休みは 4 つの層で持ち、営業日は層の「休みとして数える」で決める

- 状態: 承認（一部を ADR-0032 で置き換え）
- 日付: 2026-10-02

## 背景

task #191 の 2 本目（1 本目は ADR-0027: カレンダーの複数化・表示の選択・表示の組み合わせ）。持ち主との決定
（#191 のコメント、2026-10-01）:

- 休みは 4 つの層で持ち、データは分ける: (1) 営業日 = 稼働する曜日の規則 (2) 会社の公休 = 日付の一覧
  (3) 私の休み = 日付の一覧（終日）(4) 日本の祝日 = 日付の一覧（年ごとに入れる）
- **営業日 = (1) の曜日に当たり、「休みとして数える」の印の付いた (2)(3)(4) のどれにも無い日**。営業日シフト
  （ADR-0007・0009）と定常業務の回（ADR-0025）はこの判定を使う
- 全部重ねて予定を立てる: カレンダーの各表示とガントで休みの日を理由別に塗り、終日の帯に理由の名前。休みの日に
  予定を置いたら知らせる（止めない）。ガントにタスクの期間の営業日の数
- 休みの判定は表示のチェックに関係なく「休みとして数える」で決まる

これまでの営業日カレンダー（ADR-0009）は 1 つの表に曜日と祝日の一覧を持ち、繰り返しの規則が名指ししたときだけ
シフトに使っていた。

## 決定

- 4 層は **ADR-0027 の `calendars` の行**（種類 `WORKWEEK` / `DAYS_OFF`）として持ち、表示の選択と組み合わせを
  予定のカレンダーと同じ一覧で使う。`DAYS_OFF` は理由 `day_off_reason`（`COMPANY` / `PERSONAL` /
  `NATIONAL_HOLIDAY`）と「休みとして数える」`counts_as_day_off` を持つ。`WORKWEEK` は `workdays`。
  日付は表 `calendar_days_off`（層 × 日 × 名前）。層は利用者に 1 つずつ、消せない（409）、予定は入れない（422）。
  移行 `0010` で作る（後から来た利用者には一覧・休みの理由を引いたときに作る）。
- **移行**: 営業日の層の曜日は、その利用者のいちばん古い営業日カレンダーのもの（無ければ月〜金）。営業日カレンダーの
  祝日はすべて「日本の祝日」の層へ写す（どの層の休みか見分けられないので、いちばん多いものへ）。
- **営業日の判定**はドメインの `DayOffLayers`（`is_business_day` / `business_days_between` / `marks_between`）。
- **営業日シフトは層を包む**: 展開のたびに層から `BusinessCalendar` を作って `BusinessDayShiftService` に渡す
  （稼働する曜日 = 営業日の層、休みの日 = 数える層の日）。繰り返しの規則が古い営業日カレンダーを名指ししていれば、
  その祝日も休みの日に足し、「祝日だけ飛ばす」もそのカレンダーのものを使う。**名指しの無い規則も層で寄る**
  （これまではシフトしなかった）。営業日カレンダーの API と設定画面は残す（互換）。
  **→ ADR-0032 で置き換え**: 古い営業日カレンダー（API・設定画面・規則の名指し・名指しで祝日が足される効き目・
  「祝日だけ飛ばす」）は畳み、営業日シフトは 4 層だけで決まる。
- **API**: `GET /api/calendars/days-off?from&to`（期間の休みの理由。曜日の休みは `WEEKLY`。800 日まで）、
  `/api/calendars/{id}/days-off`（日を引く・足す・消す）、`POST …/days-off/japan`（その年の日本の祝日を暦から入れる）。
  `PUT /api/calendars/{id}` に `counts_as_day_off`・`workdays`。
- **画面**:
  - カレンダーの一覧を「予定」と「休み」の 2 段に分け、「休みだけ」の一括切り替えを足す。層の編集で
    稼働する曜日・休みとして数える・年ごとの日の一覧（足す・消す・日本の祝日を入れる）
  - 月・週・平日・「今日」: 表示中の層の日を理由別の地の色で塗る（祝日 / 公休 / 私の休み / 曜日の休み）。終日の帯に
    理由の名前（日に 1 本。重なれば「・」でつなぎ、色はいちばん強い理由 = 祝日 > 公休 > 私の休み の層の色）。
    曜日の休みは帯を出さず地の色だけ（毎週末に帯が並んで終日の欄が埋まるため）
    **→ ADR-0032 で置き換え**: 曜日の休みも控えめな帯で理由を出す（ほかの理由があればそちらを 1 つだけ。週表示は
    その日の列だけを下げる）
  - 休みの日に置いたら知らせる: 編集画面で保存したとき（繰り返しは今日から 62 日の回）・ドラッグで別の日へ動かした
    とき・「時間を取る」でタスクを落としたとき。数える理由だけを知らせ、止めない
    **→ ADR-0032 で置き換え**: 知らせるのはタスクだけ（分類がタスクの予定・「時間を取る」・タスクの開始と期限）。
    分類が予定のものは知らせない
  - ガント: 日の列を同じ色で塗り、見出しに理由の線と名前（ツールチップ）。タスクの期間の営業日の数を帯の右に出す
- 「今日」の画面は全部のカレンダーを出すので、層も表示の選択に関係なく全部重ねる。

## 理由

- 層を `calendars` の行にしたのは、表示のチェック・「休みだけ」・表示の組み合わせを予定のカレンダーと同じ仕組みで
  扱うため（別の表にすると、表示の状態と組み合わせの id が 2 種類になる）。
- 日付は層ごとの子表に分けた。祝日・公休・私の休みを 1 つの一覧に混ぜると、層ごとの「数える」と塗り分けができない。
- シフトの仕組みは触らずに包んだ。移植元由来の `BusinessDayShiftService` と展開の試験をそのまま生かせる。
- 曜日の休みに帯を出さないのは持ち主の「理由の名前を帯に」からの逸脱。週末ごとに帯が並ぶと終日の欄が 1 段埋まり、
  ほかの休みの名前が目立たなくなるため、地の色（と月表示のマスの色）で示す。要るなら帯を足すのは小さい。

## 影響

- 移行 `0010`（`down_revision` は `0009`）。下げると層と日付は消える（営業日カレンダーは元のまま）。
- 名指しの無い営業日シフトの規則は、移行の後は層で寄る（月〜金・層の休みの日を避ける）。
- 編集画面の「営業日カレンダー」の選択（ADR-0009）は残している（名指しすると祝日の足し・「祝日だけ飛ばす」に効く）。
  畳むかどうかは使われ方を見て決める。**→ ADR-0032 で置き換え**: 選択欄と名指しは畳んだ（移行 `0013` で名指しを外した）。
