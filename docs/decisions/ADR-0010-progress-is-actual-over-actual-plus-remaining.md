# ADR-0010: 進捗率は「実績 ÷（実績 ＋ 残）」、残は手で持つ

- 状態: 承認
- 日付: 2026-10-01
- 関連: task #165（式の食い違い）・#154（打刻）・#161（締め）・S8（残を見直す）

## 背景

実装は「進捗率 = 実績 ÷ 見積（上限 100%）」で、残は列を持たず「見積 − 実績」から出していた。
設計書 §5.1 は「実績 ÷（実績 ＋ 残）」。打刻と締め（#154・#161）で実績が正しく取れるようになると、
**見積を超えたタスクは 100% に張り付いたまま**になり、「あとどれだけか」が見えなくなる。

## 決定

- `tasks.remaining_hours`（`NUMERIC(6,2)`、空を許す）を足し、**残を手で持つ**（移行 `0004`）。
  実績は今までどおり `work_logs` の合計（打刻は締めで `work_logs` になる。ADR-0008）。
- **残の決め方**（`Task.remaining_hours_from`）
  1. DONE は 0（手の値は消さない。開け直したら手の値に戻る）
  2. 手で入れた値があればそれ
  3. 空なら「見積 − 実績」（負にしない）を既定にする
  4. 見積も空なら決まらない（None）
- **進捗率**（`WorkFigures.progress_percent`）= 実績 ÷（実績 ＋ 残）× 100、小数 1 桁。
  DONE は 100。**残が決まらないとき・分母が 0 のときは null**（画面は「—」）。
- **子を持つタスクは積み上げ**（`TaskProgressBoard`）。自分と全子孫の実績の合計と、子孫のうち
  子を持たないもの（葉）の残の合計を同じ式に通す。
  - 親・中間のタスク自身の残（見積・手の値）は数えない（子と二重に数えないため）。編集画面でも入れさせない
  - CANCELLED の葉は実績だけ数え、残は 0（やらない仕事は親の完了を止めない）
  - 葉の残がどれも決まらないなら、積み上げの残も決まらない（null）
- 一覧・詳細・ダッシュボード（今日のタスク）・ガントはすべて同じ `TaskProgressBoard` を通す。
  応答には自分の `actual_hours` / `remaining_hours` / `remaining_hours_entered` と、
  式に入れた `rollup_actual_hours` / `rollup_remaining_hours`、`has_subtasks` を載せる。
- API は `remaining_hours` を作成・更新で受ける（0 以上）。更新で `null` を送ると手の値を消して既定へ戻す。
  送らなければ触らない。
- 移行 `0004` は既存の行を、それまで画面に出ていた残と同じ値で埋める:
  DONE は 0、見積があれば max(見積 − 実績, 0)、見積が空なら空のまま。

## 理由

- nolumiatask と同じ考え方。見積は「最初の読み」、残は「今の読み」で、見直すのは残（S8）。
  実績 ÷ 見積は見積を超えた時点で意味を失う。
- 残が空のときに既定を「見積 − 実績」にしたのは、移行前と同じ値が出る（見積の内側では
  実績 ÷ 見積と一致する）ので、入れ直さなくても今の見え方が変わらないため。
  見積を超えたタスクは既定の残が 0 になり 100% を指すが、それは「残を見直してほしい」印として扱い、
  残を入れれば 100% から外れる。
- 判断材料が無いときに 0% と出すと「まだ手を付けていない」と区別がつかないので null にした。
- 親の残に親自身の見積を混ぜる案は、子と二重に数えるので採らなかった。

## 影響

- `progress_percent` は null を取りうる（フロントは「—」を出す）。
- ダッシュボードの「全体の進捗」は完了件数 ÷ 総件数（件数の比）で、この式とは別の指標のまま。
- Alembic 導入前の DB の引き取り（`schema_migration.adopt_legacy_schema`）は baseline に揃えるため
  古い `remaining_hours` を一度落とし、`0004` が足し直して既定の値で埋める。
