# ADR-0030: タスク一覧はプロジェクトで束ね、まとめてプロジェクトを移せる

- 状態: 承認
- 日付: 2026-10-02

## 背景

持ち主の依頼（task #187、2026-10-02）: 「https://wbs.nolumia.com/tasks ここもプロジェクトが欲しい」。

これまでの `/tasks` は、タイトルの下に小さく道筋（`project_path`）を出すだけだった。絞り込みはサイドバーの
「表示するプロジェクト」（ADR-0024 の 3）だけで、一覧の画面の中ではプロジェクトが見えない・選べない・
移せなかった。タスクを移すには 1 件ずつ編集画面を開くしかなかった。

## 決定

### 1. 絞り込みはサイドバーと同じ状態を一覧の上にも置く

一覧のツールバーの先頭に「プロジェクト」（すべて / 未分類 / 木）を置く。中身はサイドバーの
`ProjectScopeSelect` と同じ部品・同じ状態（`useProjectScope`、端末に覚える）で、どちらで替えても
もう一方が付いてくる。2 つ目の状態は作らない（「一覧ではこれ、ガントではあれ」とずれると、何が
絞られているかが読めなくなる）。選んだ値は名前ではなく道筋（「仕事 / 案件 A」）で見せる。

### 2. 「プロジェクト別」と「一覧」の切り替え（既定はプロジェクト別）

- **プロジェクト別**: プロジェクトの木の見出しの下にタスク、子プロジェクトは入れ子。見出しに**子孫まで
  含めた**タスクの数と残の合計（済み・中止は数えない。残の決まらないものも数えない）。タスクの無い枝は
  出さない。未分類は最後。範囲でプロジェクトを選んでいれば、それを最上位にする（最上位は道筋で見せる）。
  見出しは畳める。見出しの「＋」でそのプロジェクトにタスクを作る（`/tasks/new?project=<id>`）。
  束の中では子タスクを親の直後に字下げして並べる（並べ替えは兄弟の間に効く）。
- **一覧**: 今までの表に「プロジェクト」の列を足した（並べ替えは木の順 → 未分類は最後）。スマホ幅では
  列を隠し、題名の下に道筋を出す。
- 切り替えは端末に覚える（`localStorage`。失われても困らない好み）。
- 並べ方・束ね方は `frontend/src/projects/taskListView.ts` の純関数に置き、vitest で固定する。

### 3. まとめて移す: `POST /api/tasks/move-to-project`

`{"task_ids": [...], "project_id": <id> | null}`（null で未分類へ）。応答は、プロジェクトが替わった
タスク（`moved_task_ids`）と、届かなくなったマイルストーンを外したタスク（`detached_milestone_task_ids`）。

- **書くのは枝の根だけ**（ADR-0024 の 4: 子タスクは親タスクと同じプロジェクト）。根を移すと子孫も
  一緒に移る（選んでいない子孫も）。祖先が一緒に選ばれている子タスクは、その祖先と一緒に移る。
- **祖先を選んでいない子タスクを含めば、何も変えずに 422**（子だけ別のプロジェクトにはしない）。
  一部だけ通す形にしないのは、API を直に叩いたときに「どれが移ったか」を読み違えさせないため。
  画面はそういう子を最初から送らない（下の 4）。
- 自分のタスクでない id・他人のプロジェクトは 404（何も変えない）。消したタスクの親は居ないものとし、
  その子は根として扱う（タスクの更新と同じ）。
- 届かなくなったマイルストーンは外す（ADR-0024 の 5 と同じ）。
- 1 回で 500 件まで。選び分けはドメインの `TaskBranchSelection`（画面の `planProjectMove` と同じ決まり）。

### 4. 子タスクを選んだときの見せ方

- 親を選ぶと、表に出ている子孫のチェックは「親と一緒に移ります」の印（チェック済み・押せない）になる。
- 親を選ばずに子だけ選ぶと、行に「親タスクに従うため移しません」と出し、上の帯と確認の画面に
  「子タスク N 件は移しません。移すなら親を選んでください」と数で出す。移すのは残り（根）だけ。
- 親と一緒に移る子の数（選んでいない子孫も含む）も、押す前に出す。
- 選べるのは、いま見えているタスクだけ（絞り込みで隠れたものを知らずに移さない）。

### 5. 新しいタスクの既定のプロジェクト

`/tasks/new?project=<id>`（束の見出しの「＋」）を最優先、無ければ絞り込み中のプロジェクト
（ADR-0024 のまま）。`?project=none` は未分類。

## 理由

- 一覧で束ねるのは、締め・打刻のタスクの選び方（ADR-0026）と同じ「木の見出しの下にタスク」の形に
  揃えるため。違う形を 2 つ覚えさせない。
- まとめて移す口を別に作ったのは、1 件ずつ `PUT` すると、途中で失敗したときに半分だけ移った状態が
  残り、マイルストーンの外しも件数分走るため。1 回の書き込み（1 トランザクション）にした。
- 子タスクを親から切り離して移す口は作らない（ADR-0024 の 4 を崩さない）。
