# ADR-0034: カレンダーの表示と管理を別の画面に分け、日の一覧は日付を押したときだけ開く

- 状態: 承認（カレンダーの画面での表示の切り替えの置き場所・歯車の位置は ADR-0035 で置換）
- 日付: 2026-10-02

## 背景

持ち主の指摘（2026-10-02、`/calendar`）:

1. 終日の帯と時間グリッドの境目が見分けにくい（線が無い）。
2. タスクに触ると「選んだ日の予定一覧」（`SelectedDayPanel`）が出て邪魔。しかも × を押さないと閉じない。
3. カレンダーの表示と、カレンダーの管理（メンテ）は別の画面が良い。

下見で確かめた 2 の原因: 週・平日・日の表示では、次のどれに触っても `onSelectDate` / `onSelectSegment` が呼ばれ、
日の一覧が開いていた。

- 期限のチップ（タスク・マイルストーン）
- 予定・タスクのブロック（「時間を取る」で作ったタスクの予定も）
- 時間グリッドの空き枠（作成のダイアログと同時に開く。タスクの一覧で選んだタスクを置いたときも）
- 終日の帯の空いたところ

閉じる口は × と週を送ることだけで、外側・Esc・もう一度押す、では閉じなかった。

3 は、ADR-0027・0029・0032・0033 で足した管理（カレンダーの追加・名前と色・仕事/プライベート・休みの層の色と
稼働する曜日と日付・祝日の取り込み・「休みとして数える」・表示の組み合わせの保存と上書き）が、毎回使う
表示の切り替え（チェック）と同じ左の列に並んでいた。管理は月に 1 度もしない操作で、毎回の表示の切り替えを押し下げていた。

## 決定

### 日の一覧（`SelectedDayPanel`）

- **開くのは「この日の一覧を見たい」と押したときだけ**: 週・平日・日の表示の見出しの日付と、月表示のマス。
- それ以外に触ったときは開かず、触ったものの操作がその場で起きる:
  - 予定・タスクのブロック（時間グリッド・終日の帯） → 編集のダイアログ（「今日」の画面と同じ。ADR-0022）
  - 期限のチップ → そのタスクの編集画面（マイルストーンはマイルストーンの画面）。「今日」の画面でも同じ
  - 空き枠 → 予定を作る（「時間を取る」の最中はそのタスクの予定を作る）
  - 終日の帯の空いたところ → 何もしない
- **閉じ方**: ×・同じ日をもう一度押す・一覧の外を押す・Esc・見出し（狭い画面は上の取っ手）を下へ払う。
  一覧から開いた編集のダイアログの Esc はダイアログだけを閉じる。別の日の見出しを押せばその日へ移る。
- 開く条件・閉じる払い方は `frontend/src/calendar/dayPanel.ts` の純関数（`opensDayPanel`・`nextSelectedDate`・
  `isDismissSwipe`）に置き、試験する。
- 置き場所はカレンダーの下のまま（出るのは頼んだときだけになったので、常時の場所取りではなくなった）。
  狭い画面は一覧の高さを画面の 32% までにし、払って閉じる取っ手を付ける。

### 表示と管理の画面

- **カレンダーの画面（`/calendar`）には表示の切り替えだけ**を置く（`CalendarVisibilityPanel`）:
  カレンダーごとのチェック・表示の組み合わせを当てる・すべて表示 / 休みだけ / 仕事だけ。
  狭い画面では今までどおり上で折りたたむ。見出しの横の歯車から管理の画面へ行く。
- **管理は「カレンダーの設定」（`/calendar/settings`）へ移す**（`CalendarSettingsPage`）:
  予定のカレンダー（追加・名前と色・仕事/プライベート・削除）、休みの層（色・稼働する曜日・休みとして数えるか・
  日付の追加と削除・祝日の取り込み）、表示の組み合わせ（追加・名前と中身の編集・削除）。
- 表示の組み合わせは「今の表示を保存 / 上書き」をやめ、**名前と入れるカレンダーを選んで作る・直す**形にした
  （作るときの初期値は今の表示）。管理の画面からは表示中のチェックが見えないので、中身を明示して選ぶ。
- サイドバーには項目を足さない（入口はカレンダーの画面の歯車だけ。管理は頻度が低い）。

### 終日の帯の線

- 終日の帯の下に、時間グリッドとの境の線（2px・グリッドの線の色）を引く。正時の線（1px）より太くして、帯の終わりを
  見分けられるようにする。`WeekView` は週・平日・日の表示と「今日」の時間グリッドで共通の部品なので、どれにも出る。
  締めの格子（`ClosingGrid`）は終日の帯を持たず、見出しの下に既に線がある。

## 理由

- 日の一覧は移植元（NolumiaScheduler）の「日を選ぶと下に一覧」をそのまま持ってきたもので、週表示では
  ほぼすべての押下が「日を選ぶ」を兼ねていた。押したものと関係のない一覧が開くのは、押した意図（タスクを見たい・
  予定を直したい）と結果がずれている。「今日」の画面は既にブロックを押すと編集を開く作りで、そちらに揃えた。
- 一覧そのものを無くす案は採らない。狭い画面では 1 日の予定の時刻・場所・済みを並べて読める唯一の場所で、
  月表示ではマスが小さく、日の一覧が中身を読む手段になっている。
- 管理を同じ画面のダイアログに残したまま折りたたむ案は採らない。表示の切り替え（毎回）と管理（まれ）が同じ列に
  並ぶ限り、頻度と目立ち方の逆転は解けない。別の画面にすれば、カレンダーの画面の左の列は軽くなり、管理の画面は
  説明（休みの層の意味など）を書ける広さを持てる。

## 影響

- 週表示でブロックを 1 回押すと編集が開く（前は 1 回目で一覧、編集は一覧の鉛筆か 2 回押し）。ブロックの選択枠
  （`selectedSegmentKey`）はカレンダーでは使わなくなった。
- 期限のチップを押すとタスクの画面へ移る（前は日の一覧が開き、一覧のチップを押すと移った）。
- 表示の組み合わせを作るには管理の画面へ行く。
- `CalendarListPanel` は `CalendarVisibilityPanel`（表示）と `CalendarSettingsPage`（管理）に分けて消した。
