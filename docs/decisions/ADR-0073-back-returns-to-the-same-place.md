# ADR-0073: 「戻る」で戻ったら、見ていた位置へ戻す（全画面）

- 状態: 承認
- 日付: 2026-11-17
- 関連: task #1081（親 #1063）、雛形 fastapitemplate の ADR-0107（同じ形）、Scheduler の ADR-0075・Tracker の ADR-0080（同じ形）

## 背景

タスクの一覧などから詳しい画面を開き、ブラウザの「戻る」で戻ると、いつもいちばん上から表示される。長い一覧では
見ていた場所を毎回探し直すことになる（全アプリ共通の task #1063。雛形 fastapitemplate で直し（ADR-0107）、
派生アプリへ写す）。

ブラウザは「戻る」で前の位置へ戻そうとするが、WBS の画面はデータが届くまで本文を描かない
（react-query で取ってから描く）。戻した瞬間のページは短く、位置は先頭に切り詰められる。さらに SPA なので、
リンクで別の画面を開いたときも位置はそのまま残る。

## 決定

1. `App.tsx` の `<BrowserRouter>` のすぐ内側に置いた `HistoryScroll` で `hooks/useHistoryScroll.ts` の
   `useHistoryScroll()` を 1 回呼び、**全画面に効かせる**。画面ごとには何も書かない。
2. 窓の縦の位置を**履歴の 1 件ごと**（react-router の `location.key`）に `sessionStorage` へ控える
   （スクロールのたび）。ブラウザ自身の復元は切る（`history.scrollRestoration = 'manual'`）。
   訪れた最初の画面（`key` が `default`）には、履歴の状態（`history.state.key`）へ自前の名前を書き込んで見分ける。
3. **戻る・進む（POP）のときは、ページが控えの位置まで届く高さになるのを待って戻す**（`ResizeObserver`）。
   待つのは最大 5 秒（過ぎたら届く所まで戻す）。待つ間に利用者が自分で動かした（ホイール・タッチ・キー・クリック）ら
   やめる。
4. **リンクで別の画面（パスが変わる）を開いたら先頭から**。同じ画面で問い合わせ（絞り込みの `?` など）だけが変わる
   移動と `#` へのリンクは位置を変えない。
5. 直に書き換えられる表（`components/grid/EditableGrid.tsx`、ガントの左の表）は、選んだ升目を見える所へ寄せる。
   **寄せるのは選択が動いたときだけにし、表を描いた最初の 1 回は寄せない。** 最初は左上の升目が選ばれているので、
   控えのデータから表が一度に描けたとき、戻した位置をいちばん上へ引き戻してしまうため。

## 理由

- 雛形と同じ作りにそろえる。画面ごとに「描けたか」を渡させる形は、画面を足すたびに呼び忘れが起きる。
  「高さが足りたら戻す」なら画面の作りを知らずに外枠だけで決まる。
- WBS の画面は窓で流れる（外枠 `Layout` の本文は `overflow` を持たず、ヘッダーと左のメニューは
  `position: sticky`）。自前のスクロール領域で一覧を流す画面は無い（ガントの右は横にだけ送る箱）ので、
  窓だけを扱えば足りる。
- 後読み（下へ送ると読み足す一覧）は無い。データが届けば高さは足りる。
- 外枠の `App` は `<BrowserRouter>` の外にあるので、hook は中に置いた小さな部品で呼ぶ。
- 試験は jsdom と testing-library で描いて確かめる（このアプリでは初めて部品を描く試験なので、開発用の依存に
  `jsdom`・`@testing-library/react`・`@testing-library/dom` を足した。ほかの試験は今のまま node で走る）。

## 影響

- 控えは `sessionStorage` の `history-scroll:` で始まる名前に溜まる（タブを閉じれば消える）。
- リンクで別の画面を開くと先頭から出るようになった（今までは前の画面の位置が残っていた）。
- ガントの表は、開いた直後に左上の升目へ画面を寄せなくなった（矢印キーなどで選択を動かせば今まで通り寄せる）。
