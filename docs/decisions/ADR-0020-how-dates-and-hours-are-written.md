# ADR-0020: 日付と時間の書き方

- 状態: 承認
- 日付: 2026-10-01

## 背景

画面ごとに日付と時間の書き方がばらばらだった（task #151 の指摘）。

- 日付: 実績の画面は API の値をそのまま `2026-09-02〜2026-09-30` と出し、締めの知らせ・ガントは `9/16〜9/30`、
  タスクの一覧・マイルストーン・インボックス・作業ログは `2026/09/30` だった。書く関数も `utils/format.ts`・
  `closingPeriods.ts`・`FindingsPanel.tsx`・`GanttChart.tsx` に散っていた。
- 時間: 実績の画面の確定実績は `74.44h`（時間の小数）、「今日」の実績は `4:10`（時:分）。関数も
  `taskScheduling.formatHours`・`actualsView.formatSeconds`・`todayView.formatDuration`・
  `timerState.formatElapsed`・`closingBoard.formatExactDuration` に分かれていた。

## 決定

### 日付

文の中・表の中の日付は **`M/D`（ゼロ埋めしない）**。**今年**（利用者のタイムゾーンでの「今日」の年）でなければ
**`YYYY/M/D`**。期間は `{from}〜{to}`（英語は `{from} – {to}`）で、初日は上の決まりどおり、末日は初日と同じ年なら
年を省く（`9/2〜9/30`、`2025/12/16〜12/31`、`2025/12/16〜2026/1/15`）。

書くのは `frontend/src/utils/format.ts` の `formatDate`（1 日）と `dateRangeParts`（期間の両端）だけ。

例外（通さない）:

- カレンダーの題名・週の範囲・日の見出し（移植元 NolumiaScheduler の書式 `yyyy/MM/dd (ddd)`・`yyyy年M月` を保つ）
- 締めの画面の見出し `2026年 9/16〜9/30`（どの年の期間かを常に見せる。`periodLabelParts`）
- ガントの日の軸（列が狭い。年は範囲の外で分かる）
- 日付の入力欄（`<input type="date">` の値）

### 時間

量の種類で 2 つに分ける。

| 量 | 書き方 | 関数 | 使う場所 |
|---|---|---|---|
| **工数**（見積・予定済み・残・未予定・実績の合計・確定実績・差・予定） | 時間の小数 `1.5h`（小数 2 桁まで、末尾の 0 は落とす） | `formatHours` / `formatSecondsAsHours` / `formatSignedSecondsAsHours` | タスクの一覧と編集、カレンダーのタスク欄、「今日」のまだ時間を取っていないタスク、実績の画面、ガントの実績 |
| **打刻**（走っている経過・今日の打刻の合計と内訳・締めの表・重なりの長さ） | 時:分 `4:10`（正確な長さと走っている経過は `4:10:05`） | `formatClockDuration` / `formatExactDuration`、締めの表は 15 分丸めの `formatQuarterHours` | タイマー、「今日」の実績、締めの画面 |

## 理由

- **日付**: 使う日はほとんど今年の中で、年は情報を持たない。`2026-09-02` は機械の書き方で、画面のほかの場所
  （締めの知らせ・ガント・カレンダーの日の見出し）がすでに `M/D` だった。一方、年をまたぐ期間・去年のタスクの期限は
  年が無いと読み違えるので、今年でないときだけ足す。ゼロ埋めは日本語の画面では読みにくく、ほかの `M/D` とも揃わない。
- **時間**: 工数は見積と足し引きして比べる量で、外の工数・勤怠の仕組みへの書き出し（CSV）も時間の小数。`74.44h` を
  `74:26` と書くと見積の `40h` と見比べにくい。打刻は時計と並べて読む量で（「10:05 から」「次の予定 23:00」の隣に出る）、
  `0.33h` より `0:20` のほうが速く読める。締めの表は #163 の決まりで 15 分単位の `H:MM`。
- どちらか 1 つに寄せる案も考えた。全部 `H:MM` にすると見積・残（`12.5h`）まで時:分になり、入力欄（`残（h）`、0.25 刻み）
  と書き方が食い違う。全部 `h` にするとタイマーの経過が `0.07h` のように動き、時計として読めない。

## 影響

- 書く関数は `utils/format.ts` に集めた。`taskScheduling.formatHours`・`actualsView.formatSeconds`/`formatSignedSeconds`・
  `todayView.formatDuration`・`timerState.formatElapsed`・`closingBoard.formatExactDuration` は消した。新しく日付や時間を
  出すときはここの関数を使い、上の表のどちらの量かで選ぶ。
- 「今日」の画面には両方が並ぶ（実績の `4:10` と、まだ時間を取っていないタスクの `未予定 6.5h`）。量が違うので書き方も違う。
- 期限の `2026/09/30` は `9/30` になる（今年のとき）。
