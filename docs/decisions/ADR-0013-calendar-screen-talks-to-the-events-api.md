# ADR-0013: カレンダーの画面は予定 API へ「呼び出しのデータ」で書き、元に戻すも API 越しに行う

- 状態: 承認
- 日付: 2026-10-01
- 関連: task #157（カレンダー画面）・#158（週表示のドラッグ）・#156 / ADR-0009（予定の表と API）

## 背景

#157 の第 1 段で表示の部品、#158 でドラッグの意図の口（`onCreateRange` / `onRescheduleOccurrence`）と
元に戻す履歴の器（`calendar/operationHistory.ts`）を作り、#156 で予定 API ができた。この段で `/calendar` を
部品に置き換え、API と繋ぐ。決めることは 5 つ: 書き込みの組み立て方と試験の仕方、ドラッグの元に戻すの当て方、
版の食い違い（409）の扱い、編集画面のタイムゾーンと種類の変更、タスクの期限の出し方。

## 決定

### 書き込みは「呼び出しのデータ」を組み立てて、1 か所から送る

- 画面の意図（ドラッグ・元に戻す・削除）は `frontend/src/calendar/calendarRequests.ts`、編集画面の保存は
  `frontend/src/calendar/eventForm.ts` の純関数が `CalendarRequest`（method・url・body・params）に直す。
  送るのは `frontend/src/api/calendar.ts` の `sendCalendarRequest` だけ。
- 編集画面の入力（`EventForm`）は移植元 `EventEditViewModel` の欄を写し、API の応答 → 入力（`formFromEvent`）と
  入力 → 規則（`buildRecurrence`）を対にする。
- vitest は DOM を持たない（`node` 環境・純関数だけ）ので、応答 → 部品の入力と、意図 → 呼び出しの変換を
  この純関数で試験する。

### ドラッグと元に戻す

- 単発: `PUT /calendar/events/{id}`。この口は詳細を置き換えるので、送る前に予定を読み、題名・場所・メモ・
  タスクをそのまま載せて時刻だけ変える。
- 繰り返しの回: `POST .../occurrences/move`（この回だけ移動）。
- 元に戻す: 単発は `before` の時刻で PUT し直す。繰り返しの回は、**動かす前に振替でなかった回なら
  `cancel-move`（振替を消して系列の位置へ）**、振替だった回なら前の振替先へ `move` し直す（移植元
  `HadMoveBeforeDrag`）。やり直しはもう一度 `after` へ。
- 履歴の 1 件（`RescheduleEntry`）は当てた後の予定の版を持ち、戻す・やり直すたびに同じ予定の履歴すべての版を
  新しい版へ揃える（同じ予定を続けて動かしても、戻すときに古い版で 409 にならない）。
- 応答を待たずに一覧のその回を新しい位置へ置き換えて見せ、書いた後に取り直す。

### 版の食い違い（409）

- 409 は「ほかで変わっていた」。回と祝日を取り直し、**履歴は捨てて**知らせる（古い版を前提にした
  戻す・やり直すは当てられない）。編集画面から保存・削除したときも履歴は捨てる（予定の版が進むため）。
- 書き込みは 1 つずつ（送っている間の次のドラッグ・元に戻すは受けない）。

### 編集画面

- 既存の予定は**予定のタイムゾーンの壁時計**で開く（繰り返しの鍵がそのゾーンの壁時計なので）。閲覧者の
  タイムゾーンと違えばその旨を書き添える。新しい予定は閲覧者のタイムゾーン（利用者設定）で作り、
  `time_zone` を明示して送る。
- 終了の候補は 15 分おきの末尾に 24:00。開始以前を選んだら翌日のその時刻（日をまたぐ予定）とし、
  入力は「開始 ＋ 長さ」で持つ（開始を動かすと終了も同じだけ動く。移植元 `SetStartTimePreservingDuration`）。
- 繰り返しの回から開いたら、保存のときに「この予定のみ / これ以降 / すべて」を聞く（split / following /
  series）。「すべて」は系列の先頭の日を変えず、時刻だけ入力のものにする（振替・飛ばしの鍵を同じ候補日に
  付けたまま残す）。振替の回は範囲を聞かずに「この回だけ」で切り出す。
- 単発 ↔ 繰り返し（種類の変更）は、移植元と同じく**消してから作り直す**。API の編集の口はどれも元の種類を
  前提にしているため。2 つの呼び出しは 1 つのトランザクションにならない（作り直しが落ちたら消えたまま）。
- 「新規として作り直す」（移植元 `RecreateAsNew`）は入れていない（頼まれた範囲は 3 つ）。アラームは #155 で後回し。

### タスクの期限

- 前の `/calendar` が出していたタスクとマイルストーンの期限は、**予定にせず**、終日の帯（週）とマスの
  チップ（月）に**地を塗らない枠だけのチップ**（左に色の帯・頭にチェック / 旗の印・済みは打ち消し線）で
  予定の後に積む。押すとその日を選び、選んだ日の一覧から開ける（タスクは `/tasks/{id}`）。
- 予定の「タスク（任意）」は WBS のタスクを選ぶ（打刻の既定のタスクになる。ADR-0008 / 0009）。

### 営業日カレンダーと祝日

- 個人設定（`/settings`）に「営業日カレンダーと祝日」の欄を足した（作る・名前・営業日・休日のみシフト・
  有効・消す、祝日の追加・削除、日本の祝日を年で入れる）。設定画面がカードを縦に並べる作りなので、
  別のルートにしなかった。

## 理由

- **呼び出しをデータにした**: 意図 → API の変換を、HTTP を差し替えずに試験できる。jsdom や Testing Library を
  足すと lockfile が変わる（この段では依存を足さない決まり）。
- **元に戻すを「前の時刻へ動かす」にしなかった（繰り返しの回）**: 振替でなかった回を `before` の時刻へ
  振り替えると、系列の位置と同じ時刻の「振替」が残り、系列を直したときに付いてこない。
- **409 で再試行しなかった**: 自動で当て直すと、ほかで変えた中身を黙って上書きする。
- **期限を予定の型に混ぜなかった**: 予定の型（`CalendarOccurrence`）は API の応答のままにしておきたい。
  期限は動かせず時刻も持たないので、置き場所（終日の帯）だけ共有し、型と見た目を分けた。

## 影響

- 見本ページ `/calendar-preview` は消した。表示の部品の確かめは `/calendar` で行う。
- 月表示のチップはドラッグできない（移植元にも無い）。
- ダークモードの色（`palette.calendar` の暗い側）は部品に残っているが、アプリ全体が明るいテーマのままなので
  使う画面はまだ無い。
