## 詳細

1. **T1（DB 方針）** — 設計書 3.3.3 / 4.2 は MariaDB 10.6+（ネイティブ ENUM・トリガー・
   ビューを DDL 前提）だが、現行雛形と CLAUDE.md のテスト方針は SQLite ベース。どちらを
   採用するかで T3 以降の実装が変わる。ENUM はネイティブ型を使わず `native_enum=False`
   とする点、`v_task_summary` / `v_today_tasks` とトリガー `trg_tasks_before_update` を
   DB 側に置くかアプリ層で再現するかも本項で決める。
2. **T2（サンプル撤去）** — `src` 配下の `Item` エンティティ・ユースケース・API・テスト
   （`domain/entities/item.py`、`application/use_cases/*`、`presentation/api/routers/items.py`
   など）を残すか撤去するかを決める。ドメイン語彙を Task Scheduler に合わせるため撤去が基本線。
3. **T3（スキーマ）** — Alembic マイグレーションで管理（`ALTER`/`CREATE` の直接実行禁止）。
   `tasks` の CHECK 制約（priority/urgency 1–5、日付整合、自己参照禁止）も移植する。
4. **T6（今日のタスク）** — 抽出条件は設計書 5.3、bucket 分類とスコア計算を含む。ビューを
   使わない場合は同等のクエリをリポジトリ層で実装する。
